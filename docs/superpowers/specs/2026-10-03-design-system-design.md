## 2. 설계 원칙

| # | 원칙 | 뜻 |
| --- | --- | --- |
| P1 | **토큰 하나, 패턴 두 벌** | 색·글자·간격·둥글기·아이콘은 하나의 토큰을 공유한다. 화면을 짜는 방식만 휴대폰(iOS식 묶음 리스트)과 PC 관리(데이터 테이블)로 나눈다 |
| P2 | **색은 상태를 알릴 때만** | 강조색은 검정 하나. 초록·노랑·빨강은 상태 칩과 경고에만 쓴다. 그라디언트는 쓰지 않는다 |
| P3 | **그림자 대신 면과 선** | 구분은 배경색 차이와 얇은 선으로 한다. 그림자는 시트·팝오버·토스트처럼 떠 있는 것에만 쓴다 |
| P4 | **정해진 단계만 쓴다** | 글자 7단계, 둥글기 4단계, 간격은 4의 배수. 그 밖의 값은 쓰지 않는다 |
| P5 | **동작은 빌리고 모양은 만든다** | 포커스·ESC·스크롤 잠금 같은 동작은 이미 설치된 `@headlessui/react`에 맡기고, 모양만 직접 만든다. shadcn/ui 같은 기성 모양은 들이지 않는다 |
| P6 | **컴포넌트에 색 값을 직접 쓰지 않는다** | `bg-blue-500`, `#3b82f6` 대신 `bg-surface`, `text-secondary` 같은 역할 이름만 쓴다. 다크모드를 나중에 넣기 위한 조건이다 |

## 3. 토큰

토큰은 `src/styles/globals.css`의 CSS 변수로 정의하고, `tailwind.config.ts`에서 그 변수를 가리키는 이름을 만든다. 컴포넌트는 Tailwind 클래스(`bg-surface`, `text-body`)로만 쓴다.

### 3-1. 색 (역할 이름)

대비는 WCAG 계산값이다. 본문 글자는 4.5:1 이상을 지킨다.

| 토큰 | 값 (라이트) | 쓰는 곳 | 대비 |
| --- | --- | --- | --- |
| `bg` | `#F2F2F7` | 화면 바탕 | — |
| `surface` | `#FFFFFF` | 묶음 리스트, 카드, 시트, 테이블 | — |
| `surface-muted` | `#FAFAFB` | 테이블 머리줄, 일괄 처리 바 | — |
| `fill` | `#E5E5EA` | 보조 버튼 배경, 선택된 사이드바 항목, 세그먼트 바탕 | — |
| `text` | `#1C1C1E` | 본문, 제목 | 흰 바탕 17.0 / `bg` 15.3 |
| `text-secondary` | `#636366` | 부가 정보, 라벨 | 흰 바탕 6.0 / `bg` 5.4 |
| `text-tertiary` | `#8E8E93` | 입력칸 안내 문구, 비활성 탭 아이콘. **뜻이 있는 글자에는 쓰지 않는다** | 흰 바탕 3.3 |
| `separator` | `#C6C6C8` | 리스트 항목 사이 0.5px 선 | — |
| `border` | `#E5E5EA` | 테이블·입력칸 테두리 1px | — |
| `accent` | `#1C1C1E` | 주 버튼, 선택된 탭, 체크박스, 링크 | — |
| `on-accent` | `#FFFFFF` | `accent` 위의 글자 | 17.0 |
| `scrim` | `rgba(0,0,0,0.4)` | 시트 뒤를 덮는 반투명 막 | — |

### 3-2. 상태색

의미별 네 가지뿐이다. 연한 배경 + 진한 글자의 칩으로 쓴다.

| 톤 | 배경 / 글자 | 대비 | 도메인 상태 |
| --- | --- | --- | --- |
| `positive` (초록) | `#E3F5E8` / `#176B34` | 5.8 | 참석, 납부, 게스트 `APPROVED`, 대회 입금 `CONFIRMED`, 대회 `OPEN` |
| `warning` (노랑) | `#FFF2D9` / `#8A5A00` | 5.4 | 대기, 미납, 게스트 `PENDING`, 대회 입금 `PENDING` |
| `negative` (빨강) | `#FDE7E5` / `#B3261E` | 5.5 | 불참, 연체, 게스트 `REJECTED`, `CANCELED` |
| `neutral` (회색) | `#EFEFF2` / `#636366` | 5.2 | 미응답, 휴면, 대회 `CLOSED`·`DRAFT`, 회원 `APPROVED`(활동)·`ON_LEAVE`·`LEFT` |

- 시안에서 쓴 초록 글자(`#1B7F3B`, 대비 4.5 미만)와 회색 글자(`#6E6E73`)는 대비를 맞추려고 한 단계 진하게 바꿨다.
- 삭제 같은 위험한 버튼은 `negative` 글자색(`#B3261E`)을 쓴다. 흰 바탕에서 6.5:1.
- 도메인 상태 → 톤 대응은 **한 파일**(`src/constants/statusTone.ts`)에서만 정한다. 화면에서 `status === 'APPROVED' ? 'green' : ...` 같은 분기를 쓰지 않는다.

### 3-3. 글꼴과 글자 크기

- **글꼴:** Pretendard. npm 패키지 `pretendard`의 가변 글꼴(필요한 글자만 나눠 받는 dynamic subset)을 `_app.tsx`에서 불러온다. 대체 글꼴은 `-apple-system, 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif`.
- **이유:** Mac·아이폰에서는 시스템 글꼴과 거의 같아 보이지만, 갤럭시(One UI 글꼴)와 윈도우(맑은 고딕)에서도 같은 모양으로 보이게 하려는 선택이다.
- **숫자:** 금액·인원·전화번호·날짜는 `tabular-nums`(고정폭 숫자).

| 토큰 | 휴대폰 (크기/줄높이/굵기) | PC 관리 | 쓰는 곳 |
| --- | --- | --- | --- |
| `large-title` | 28 / 34 / 700 | 24 / 30 / 700 | 화면 제목 |
| `title` | 22 / 28 / 700 | 20 / 26 / 700 | 시트 제목, 큰 섹션 제목 |
| `headline` | 17 / 24 / 600 | 15 / 22 / 600 | 리스트 항목 이름, 카드 제목 |
| `body` | 16 / 24 / 400 | 14 / 20 / 400 | 본문, 입력칸, 테이블 셀 |
| `callout` | 15 / 22 / 400 | 14 / 20 / 400 | 보조 설명 |
| `footnote` | 13 / 18 / 400 | 13 / 18 / 400 | 날짜·장소 같은 부가 정보 |
| `caption` | 12 / 16 / 500 | 12 / 16 / 500 | 상태 칩, 탭 라벨. 가장 작은 크기 |

- 제목 두 단계는 자간 −0.02em, `headline`은 −0.01em.
- **PC 관리용 크기를 내는 방법:** 글자 크기도 CSS 변수로 둔다. 관리 화면의 본문 영역에 `data-density="compact"`를 달면 그 안에서만 변수 값이 PC 관리 열의 값으로 바뀐다. 컴포넌트는 `text-body`만 쓰면 되고, 밀도를 알 필요가 없다. `compact`는 `lg` 이상 폭에서만 효과가 있다(휴대폰으로 관리 화면을 열면 휴대폰 크기).
- 휴대폰의 입력 요소는 언제나 16px 이상이다(아이폰에서 입력칸을 누를 때 화면이 확대되지 않게).
- 적용 뒤 아이폰·갤럭시·윈도우 PC 실기기에서 보고 값을 조정한다. 토큰 값만 바꾸면 된다.

### 3-4. 모양과 간격

| 항목 | 토큰 / 값 | 쓰는 곳 |
| --- | --- | --- |
| 둥글기 `sm` | 8 | PC 관리의 버튼·입력칸·사이드바 항목 |
| 둥글기 `md` | 12 | 휴대폰의 버튼·입력칸, 묶음 리스트, 테이블 바깥 |
| 둥글기 `lg` | 16 | 시트의 위쪽 모서리, 가운데 모달 |

| 화면 좌우 여백 | 16 (휴대폰) / 24 (PC 본문) | `Layout`만 담당한다. 페이지가 다시 여백을 주지 않는다 |
| 묶음 사이 | 24 | 리스트 묶음과 묶음 사이 |
| 리스트 행 | 최소 높이 44, 안쪽 여백 12 / 16 | |

| 쌓임 순서 | `tabbar` 30 · `dropdown` 40 · `sheet` 50 · `toast` 60 | 지금은 `z-50`에 12곳이 몰려 있다 |

### 3-5. 아이콘과 움직임

| 항목 | 규칙 |
| --- | --- |
| 아이콘 | `lucide-react` 하나만 쓴다. 선 굵기 2. 크기는 탭바 22, 기본 20, PC 관리 16. 이모지 아이콘과 인라인 svg는 없앤다 |
| 움직임 | 150–250ms, ease-out. 시트는 아래에서 올라오고, 버튼은 누를 때 살짝 어두워진다. `prefers-reduced-motion`이면 끈다 |

### 3-6. 다크모드

지금은 라이트만 만든다. 다만 P6을 지키면 나중에 `:root`의 다크 값만 채우면 되는 구조다. 다크 값 정의와 화면 검수는 이번 범위 밖이다(8장 L1).

> **2026-10-03 갱신:** 6단계가 끝난 뒤 다크모드를 넣었다. 시스템 설정(`prefers-color-scheme`)을 따르고 앱 안의 전환 버튼은 없다. 다크 값은 `globals.css`의 `@media (prefers-color-scheme: dark)` 블록에 있고, 글자/바탕 대비는 `src/__tests__/styles/darkMode.test.ts`가 라이트·다크 모두 검사한다. 카카오 버튼과 아바타의 글자색은 강조색을 따라 뒤집히지 않도록 `on-kakao`·`on-avatar` 토큰으로 분리했다.

## 4. 부품

기존 `src/components/{atoms,molecules,organisms,templates}` 구조를 따른다. 이미 있는 atom(`Button`, `Input`, `Select`, `Textarea`, `Checkbox`, `Label`)은 **제자리에서 고친다**. 새 이름으로 하나 더 만들지 않는다. 변형은 `cva`, 클래스 병합은 `tailwind-merge`를 쓴다(둘 다 설치돼 있다).

### 4-1. 공통 부품

| 부품 | 위치 | 하는 일 | 주요 속성 |
| --- | --- | --- | --- |
| `Button` (기존) | atoms | 누르는 동작 | `variant`: primary(검정) · secondary(`fill`) · destructive(빨강 글자) · plain(글자만) / `size`: lg(48, 화면 아래 주 버튼) · md(44) · sm(보이는 높이 32, 터치 44) |
| `IconButton` (신규) | atoms | 아이콘만 있는 버튼 | 44 × 44, `aria-label` 필수 |
| `Input` · `Select` · `Textarea` · `Checkbox` (기존) | atoms | 입력 | 높이 44, 글자 `body`, 둥글기 `md`, `surface` 배경 + `border` 1px 테두리(흰 시트 안에서도 보이도록 어디서나 같다) |
| `FormField` (기존) | molecules | 라벨 + 입력 + 오류 문구 | `useId()`로 라벨과 입력을 연결 |
| `StatusChip` (신규) | atoms | 상태 표시 | `tone`: positive · warning · negative · neutral. 도메인 상태를 넘기면 `statusTone`으로 톤을 찾는다 |
| `Avatar` (신규, `GuestAvatar` 대체) | atoms | 프로필 사진, 없으면 이름 첫 글자 | `size`: 28 · 36 · 56 |
| `ListGroup` · `ListRow` (신규) | molecules | iOS식 묶음 리스트 | `ListGroup`에 `label`·`footer`, `ListRow`에 `leading`·`title`·`subtitle`·`trailing`·`href`/`onClick`. 누를 수 있는 행에는 오른쪽 `›` |
| `SegmentedControl` (신규) | molecules | 2–4개 중 하나 고르기 | 게시판 카테고리, 회원 필터 |
| `Sheet` (신규) | organisms | 떠 있는 창 | headlessui `Dialog` 기반. 휴대폰은 아래에서 올라오는 시트, `md` 이상은 가운데 모달. 고정 머리·고정 버튼 영역, `max-h-[90dvh]`, 홈 인디케이터 여백 |
| `ConfirmSheet` + `useConfirm()` (신규) | organisms | 확인·경고 | `confirm()` / `alert()` 호출(약 10곳)을 대체 |
| `PageHeader` (신규) | organisms | 화면 제목 영역 | `large-title` 제목, 뒤로 가기, 오른쪽 동작 버튼 |
| `EmptyState` (신규) | molecules | 내용이 없을 때 | 아이콘 + 문구 + 버튼 |
| `Skeleton` (신규) · `Spinner` (기존) | atoms | 불러오는 중 | 목록은 스켈레톤, 그 밖은 스피너 |

### 4-2. PC 관리용 부품 (5단계에서 만든다)

| 부품 | 하는 일 |
| --- | --- |
| `DataTable` | 열 정의로 그리는 테이블. 머리줄 고정, 행 선택(체크박스), 정렬, 페이지 넘김. **`lg` 미만에서는 같은 데이터를 `ListGroup`으로 그린다** — 열 정의에 "리스트에서 제목·부제·오른쪽에 무엇을 보일지"를 함께 적는다 |
| `Toolbar` | 검색칸 + `SegmentedControl` 필터 + 오른쪽 동작 버튼 |
| `BulkActionBar` | 행을 고르면 테이블 아래에 나타난다. "N명 선택됨" + 일괄 동작 버튼 |

### 4-3. 부품 사이의 경계

- atom은 토큰만 알고, 도메인(회원·운동·회비)을 모른다. 예외는 `StatusChip`이 `statusTone`을 읽는 것 하나다.
- 화면(page)은 색·크기 클래스를 직접 쓰지 않고 부품과 배치(flex·grid·간격) 클래스만 쓴다.

## 5. 앱 뼈대

### 5-1. 메뉴 — 목록 하나, 모양 둘

메뉴 항목은 설정 배열 하나(`navItems`: 라벨 · 아이콘 · 경로 · 권한 · 구역)로 관리한다. 탭바와 사이드바가 모두 이 배열을 그린다. 전환은 CSS(`lg:hidden` / `hidden lg:flex`)로만 한다. 렌더 중에 `window.innerWidth`를 읽지 않는다.

| | 휴대폰·태블릿 (`lg` 미만) | PC (`lg` 이상, 1024px~) |
| --- | --- | --- |
| 형태 | 하단 탭바 5칸 | 왼쪽 사이드바 (폭 240) |
| 항목 | 홈 · 출석 · 게스트 · 게시판 · **더보기** | 홈 · 출석체크 · 게스트 · 게시판 · 대회 + **관리** 구역 |
| 더보기 / 관리 | 더보기 화면에 대회, 내 정보, 클럽 전환, 로그아웃, (운영진) 회원 · 회비 · 게스트 확인 · 클럽 설정 | 관리 구역(운영진만 보임)에 회원 · 회비 · 게스트 확인 · 클럽 설정. 맨 아래에 내 정보 · 클럽 전환 |
| 선택 표시 | 아이콘과 라벨이 `text`색 + 굵게, 나머지는 `text-secondary` (`text-tertiary`는 12px 라벨에 대비가 모자라 쓰지 않는다) | 항목 배경 `fill` |

- 탭바 높이 56 + 아래 안전 영역(`env(safe-area-inset-bottom)`). 높이는 CSS 변수 `--tabbar-h`로 두고, 화면 아래에 붙는 버튼·토스트가 이 값만큼 위로 올라간다.
- 탭바 배경은 반투명 흰색 + 블러. 이 디자인에서 유리 질감을 쓰는 유일한 곳이다.
- 탭 5칸 구성은 `navItems`만 고치면 바뀐다. 실제 사용 빈도를 보고 조정한다(예: 대회 시즌에는 대회를 탭으로).
- 기존 상단 탭(`ClubNavigation`)과 햄버거 메뉴(`SideMenu`)는 없앤다. `SideMenu`에 하드코딩된 `/clubs/1/...` 링크 문제도 함께 사라진다.
- 메뉴는 모두 `<Link>`로 만든다.
- 로그인 화면과 외부인용 화면(`external-apply`, `external-entry`)에는 탭바·사이드바를 그리지 않는다.
- 클럽 밖의 화면(클럽 목록, 첫 화면)에는 클럽 메뉴가 없다. 다만 **내 정보**는 클럽 메뉴에서 들어가는 화면이므로 직전에 보던 클럽의 메뉴를 그대로 둔다(한 번에 돌아갈 수 있게).
- 태블릿용 아이콘 레일(09-27 계획의 중간 단계)은 만들지 않는다. 필요해지면 그때 추가한다.

### 5-2. 화면 종류별 배치

| 화면 종류 | 휴대폰 | PC |
| --- | --- | --- |
| **회원용** (출석, 운동 상세, 게스트, 게시판, 대회, 내 정보) | `PageHeader` + `ListGroup` 위주. 주 버튼은 화면 아래 고정 | 사이드바 옆에 가운데 정렬된 좁은 본문(`max-w-2xl`). 모양은 휴대폰과 같다 |
| **관리용** (회원, 회비, 게스트 확인, 대회 운영, 클럽 설정) | `DataTable`이 리스트로 바뀐다. 행을 누르면 상세 시트 | 넓은 본문 + `Toolbar` + `DataTable` + `BulkActionBar`. `data-density="compact"` |

## 6. 모노크롬 보완 원칙

모노크롬은 차갑고 딱딱해 보일 수 있다. 친목 모임 앱이므로 **강조색을 더하지 않고** 아래 방법으로 온기를 준다. 4단계에서 화면을 옮길 때마다 점검하고, 6단계에서 전체를 다시 본다.

| # | 방법 | 적용 예 |
| --- | --- | --- |
| W1 | 사진·프로필이 색을 맡게 한다 | 참가자 목록·회원 목록·댓글에 `Avatar`. 운동·대회 상세에 사진이 있으면 크게 |
| W2 | 상태색을 선명하게 | 상태 칩이 화면의 포인트가 되게 한다. 칩을 회색으로 뭉개지 않는다 |
| W3 | 말투를 부드럽게 | "참석 처리됨" → "토요일에 봬요!". 빈 화면·완료 메시지·토스트에 우선 적용 |
| W4 | 작은 움직임 | 참석 버튼을 누르면 칩이 살짝 튀며 바뀐다. 시트가 부드럽게 올라온다 |
| W5 | 클럽 색이 필요해지면 | 로고와 앱 아이콘에만 쓴다. UI 강조색은 `accent` 값 하나라 나중에 정해도 된다 |

## 7. 적용 순서

부품을 먼저 만들고 화면은 나중에 옮긴다. 단계마다 따로 머지·배포할 수 있다. **구현 계획은 단계별로 따로 쓴다**(한 번에 쓰기에는 크다). 첫 구현 계획은 1–2단계를 다룬다.

| 단계 | 하는 일 | 사용자가 보는 변화 | 의존 |
| --- | --- | --- | --- |
| **1. 토큰** | 3장의 토큰을 `globals.css`·`tailwind.config.ts`에 정의. Pretendard 적용. `statusTone.ts` 작성. 지금 정의 없이 쓰이는 클래스(`border-input`, `text-muted-foreground`, `ring-ring`, `bg-background`) 정리 | 글꼴과 화면 바탕색이 바뀐다 | — |
| **2. 기본 부품** | 4-1의 부품. 기존 atom은 제자리에서 고치므로 사용처가 함께 바뀐다. 원시 `<input>`·`<select>`·`confirm()`을 부품으로 교체 | 버튼·입력칸·모달이 새 모양이 된다. 화면 배치는 그대로 | 1 |
| **3. 앱 뼈대** | `navItems`, 하단 탭바, PC 사이드바, 더보기 화면, `PageHeader`, `Layout` 변형. 상단 탭·햄버거 제거. 페이지마다 따로 주던 여백 제거 | 메뉴가 새 모습으로 바뀐다. 체감이 가장 큰 단계 | 2 |
| **4. 휴대폰 화면** | 사용 빈도순으로 하나씩 `ListGroup` 패턴으로 옮긴다: 출석체크 → 운동 상세 → 게스트 신청·상세 → 게시판 → 대회 → 내 정보 → 로그인·가입. W1–W4 점검 | 화면이 하나씩 새 디자인이 된다 | 3 |
| **5. PC 관리 화면** | 4-2의 부품을 만들고 회원 관리에 적용. 이어서 게스트 확인·대회 운영. PC 관리용 둥글기 `sm` 적용도 이때 한다. 회비 관리는 이 부품으로 **새로 개발**한다(별도 설계) | 운영진 화면이 완성된다 | 3 |
| **6. 마감** | 남은 이모지 아이콘·옛 색 클래스·그라디언트 제거. W1–W5 전체 점검. 실기기에서 글자 크기 조정 | 전체가 통일된다 | 4, 5 |

- 4단계 동안에는 새 화면과 옛 화면이 섞인다. 3단계에서 뼈대·글꼴·부품이 먼저 통일되므로 어색함은 크지 않다.
- 4단계와 5단계는 서로 기다리지 않는다. 회비 관리 개발이 급하면 5단계를 먼저 해도 된다.
