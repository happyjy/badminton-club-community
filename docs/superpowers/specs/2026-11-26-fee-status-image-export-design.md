# 납부현황 이미지 내보내기 설계

작성일: 2026-11-26
관련 화면: 회비 관리 대시보드(`/clubs/[id]/membership-fee`)의 [납부현황 내보내기] 옆

## 1. 의도와 까닭

- **재무님은 납부현황표를 카톡방에 이미지로 올린다.**
  - 지금은 엑셀만 내보낼 수 있어, 엑셀을 열고 인쇄 쪽을 캡처하는 손작업이 든다.
  - 재무님 표는 A4 세로 한 쪽씩 캡처한 JPG 3장이다(793×1122, 38·42·12명).
- **목표: 버튼 하나로 카톡에 바로 올릴 수 있는 PNG 여러 장을 만든다.**
  - 표의 내용(줄 순서·칸 색·비고)은 엑셀과 똑같아야 한다.

## 2. 목표 · 하지 않을 것

| 구분 | 내용 |
| --- | --- |
| 목표 | 보고 있는 해의 납부현황을 40명씩 나눈 PNG로 만든다. 휴대폰은 공유 창으로 카톡에 바로 보내고, PC는 파일로 내려받는다 |
| 하지 않을 것 | 엑셀 내보내기는 바꾸지 않는다. 버튼 문구도 그대로다 |
| 하지 않을 것 | 이미지 안의 색을 라이트·다크에 맞추지 않는다. 엑셀·재무님 표와 같은 고정 색이다 |
| 실패로 볼 것 | 이미지와 엑셀의 줄 순서·칸 색·비고가 다르면, 기능이 돌아가도 실패다 (탈퇴 회원을 빼는 것만 다르다) |
| 하지 않을 것 | 이미지에는 탈퇴 회원을 싣지 않는다. 엑셀에는 그대로 남는다 (2026-11-26 사용자 결정) |

## 3. 사용자 결정 (2026-11-26)

- 형식은 PNG다.
  - 단색 칸과 글자라 JPG보다 또렷하고 파일이 작다.
- 한 장에 40명씩 나눈다(100명이면 3장).
  - 한 장으로 길게 만들면 카톡이 줄일 때 이름이 흐려지기 쉽다.
- 가로 800 기준 배치를 2배로 그려 가로 1600픽셀로 만든다.
- 만드는 방법은 A, 브라우저가 캔버스에 직접 그린다.
- 이미지에는 탈퇴 회원을 싣지 않는다 (구현 뒤 운영 데이터로 그려 보고 정함).
  - 활동 92명 + 그 해 탈퇴 29명이면 4장(마지막 장 1명)이 됐다. 재무의 표도 활동 회원만 싣는다(3장, 92명).
  - 카톡방은 지금 회원만 보고, 떠난 사람의 미납 칸까지 공개할 까닭이 없다.

## 4. 방법 (Approaches)

| 방법 | 모습 | 대가 | 결정 |
| --- | --- | --- | --- |
| A. 브라우저가 캔버스에 직접 그리기 | 서버는 줄 목록만 주고 브라우저가 그린다 | 선·칸·글자 위치를 직접 계산한다. 그림은 자동 테스트가 어렵다 | **고름** |
| B. 화면 부품을 라이브러리로 사진 찍기 | `html-to-image` 등으로 화면을 PNG로 | 새 라이브러리, 웹 글꼴 넣기가 느리고 브라우저마다 다름 | 버림 |
| C. 서버에서 PNG 만들기 | 기기와 상관없이 같은 그림 | 한글 TTF(수 MB)를 저장소에 넣어야 함, 공유하려면 브라우저가 다시 받아야 함 | 버림 |

## 5. 설계

### 5-1. 표 모델을 엑셀과 함께 쓴다

- `buildFeeStatusWorkbook` 안의 줄 순서·번호·비고·굵은 선 계산을 떼어 `buildFeeStatusSheet(rows)`로 만든다.
  - 활동 회원(직책 회원을 정렬 순서대로 먼저, 나머지 가나다순) → 탈퇴 회원(가나다순, NO 칸은 "탈퇴").
  - 비고: 직책, 지금 부부면 "부부"(둘 다면 "총무 · 부부"), 탈퇴 회원은 "YYYY.MM 탈퇴".
  - 굵은 선: 직책 회원 묶음 아래, 활동 회원과 탈퇴 회원 사이.
- 엑셀과 이미지가 이 함수 하나를 쓴다.
  - → 그래서 한쪽만 바뀌는 일이 생기지 않는다.

### 5-2. 서버: 표 모델 API

- `GET /api/clubs/[id]/membership-fee/export-sheet?year=YYYY` (관리자)
  - 엑셀 `export` API와 같은 방법으로 회원을 읽고 칸 상태를 계산해, 표 모델과 반영일(오늘, 한국 날짜)을 JSON으로 준다.
  - 탈퇴 회원은 표 모델을 만들기 전에 뺀다. 그래야 마지막 회원 아래에 탈퇴 묶음용 굵은 선이 생기지 않는다.
  - 줄마다 번호, 이름, 12달 칸 상태, 비고, 아래 선 굵기를 싣는다. 병가 사유는 싣지 않는다(2026-11-26 사용자 요청, 엑셀도 같다).

### 5-3. 브라우저: 그리기

- 장마다 제목(`YYYY년 월회비 납부현황`), 반영일, 범례(완납·미납·면제·병가·해당없음), 머리글, 회원 40명, 아래 쪽 번호(`- 1 -`)를 그린다.
  - 재무님 표와 같은 배치다.
- 칸 색은 엑셀의 `CELL_FILL`을 그대로 쓴다. 머리글은 엑셀과 같은 남색 바탕에 흰 글자다.
- 글꼴은 화면이 쓰는 Pretendard다.
  - 글꼴이 글자 묶음별로 나뉘어 있어, 그리기 전에 표에 들어갈 글자로 글꼴을 미리 불러온다(`document.fonts.load`).
- 마지막 장은 남은 줄만큼만 높이를 잡는다(빈 칸으로 채우지 않는다).
- 그리는 코드는 `src/lib/membership-fee/`에 둔다.
  - 엑셀의 고정 색처럼 표 데이터의 색이라 화면 토큰 규칙의 대상이 아니다.

### 5-4. 보내기

- 터치 기기에서 파일 공유를 지원하면(`navigator.canShare({ files })`) 확인 창을 한 번 띄운 뒤 공유 창을 연다.
  - 브라우저는 누른 직후에만 공유 창을 열게 한다. 데이터를 받고 그리는 사이에 그 시간이 지나 아이폰 사파리에서 공유가 막히기 쉽다.
  - → 그래서 다 만든 뒤 확인 창의 [공유하기]를 한 번 더 누르게 해, 그 누름으로 공유 창을 연다 (계획 단계에서 더함).
  - 카톡을 고르면 여러 장이 한 번에 간다.
  - 확인 창이나 공유 창을 닫으면 아무 일도 하지 않는다.
  - 그래도 공유가 막히면 내려받기로 넘어간다.
- 그 밖에는 PNG를 차례로 내려받는다.
- 파일 이름: `회비납부현황_YYYY_YYYYMMDD_1.png`, `_2.png`, …
  - 엑셀 이름(`회비납부현황_YYYY_YYYYMMDD.xlsx`, 날짜는 반영일)을 따른다.

### 5-5. 화면

- 툴바의 [납부현황 내보내기] 옆에 버튼을 하나 더 둔다.

| 자리 | 새 문구 |
| --- | --- |
| 버튼 | 이미지로 내보내기 (아이콘 `ImageDown`) |
| 만드는 중 | 만드는 중… |
| 내려받음 | 이미지 N장을 내려받았습니다. |
| 실패 | 이미지를 만들지 못했습니다. (서버가 사유를 주면 그 사유) |
| 공유 전 확인 창 제목 | 이미지 N장을 만들었습니다. |
| 공유 전 확인 창 버튼 | 공유하기 (닫기는 기존 확인 창의 "취소") |

- 미리보기: `/dev/admin-preview`에 가짜 데이터로 그린 이미지를 보이는 화면을 더한다.

## 6. 빌더에게 맡기는 것

- 장 안의 칸 너비·줄 높이·글자 크기의 정확한 값(재무님 표 비율을 기준으로).
- 범례 배치, 쪽 번호 위치.

## 7. 확인

- 표 모델: 줄 순서, 번호, 비고, 굵은 선, 40명씩 나누기를 테스트한다.
- 엑셀: 표 모델로 바꾼 뒤에도 기존 테스트가 그대로 통과한다.
- 그리기: 기록용 가짜 캔버스로 칸마다 칠한 색과 장 수·크기를 테스트한다.
- 보내기: 공유 지원 여부에 따라 공유·내려받기로 갈리는지, 공유를 닫았을 때 조용한지 테스트한다.
- 눈으로: 미리보기와 실제 운영 데이터로 만든 이미지를 보고, "나와의 채팅"에 일반 화질로 보내 이름이 읽히는지 확인한다.
