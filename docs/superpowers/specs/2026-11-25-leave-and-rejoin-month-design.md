# 탈퇴월·재가입 시작월 고르기 설계

작성일: 2026-11-25
범위: 질문 지도 11번 (재가입 회원 관리)
관련 메모: 탈퇴월은 마지막으로 회비를 낸 달로 둔다 (사용자 결정 2026-11-22)

## 1. 왜 (Intent)

- **탈퇴했다 돌아온 회원을 DB를 손으로 고치지 않고 앱에서 처리하려고 한다.**
  - 회원 E·회원 F·회원 G는 돌아온 뒤 예전 탈퇴일과 시작월이 남아 매칭에서 빠지거나 납부 현황이 틀렸다. 세 명 모두 손으로 맞췄다.
  - 재가입 회원은 앞으로도 생긴다.
- **탈퇴 처리도 같은 문제를 만든다.**
  - 상태를 탈퇴로 바꾸면 탈퇴일이 오늘로 들어간다.
  - 몇 달 안 내다 정리한 회원은 그 사이 달이 미납으로 남아 납부율만 낮춘다. 클럽은 그만둔 사람에게 밀린 회비를 받지 않는다.

## 2. 지금의 모습

| 상황 | 지금 동작 |
| --- | --- |
| 탈퇴한 사람이 앱에서 다시 가입 신청 | `join.ts`가 "이미 가입된 클럽입니다"로 막는다. 회원 기록이 클럽·사용자마다 하나다 |
| 재가입 | 관리자가 회원 관리 시트의 상태를 탈퇴 → 승인됨으로 바꾼다 (회원 E·회원 F도 이렇게 돌아왔다) |
| 상태를 탈퇴로 바꿈 | `status.ts`가 `leftAt = 오늘` |
| 탈퇴에서 다른 상태로 바꿈 | `status.ts`가 `leftAt = null`. 시작월은 예전 값 그대로라 떠나 있던 기간이 모두 미납이 된다 |
| 탈퇴일을 읽는 곳 | 납부 현황·직접 추가·휴회 이월 안내는 탈퇴 상태일 때만 본다. 입금 매칭(`matchableMembers`, `memberMatcher`)·확정 계획(`confirmPlanner`)·납부월 이월(`paymentShift`)은 상태와 관계없이 본다 |

- 2026-11-25 운영 DB: 탈퇴 63명 모두 탈퇴일이 있고, 탈퇴가 아닌 회원 중 탈퇴일이 남은 사람은 0명이다.

## 3. 목표 · 하지 않을 것

- **목표**
  - 상태를 탈퇴로 바꿀 때 탈퇴월을 고른다. 기본값은 마지막으로 회비를 낸 달이다.
  - 탈퇴에서 되돌릴 때 다시 시작하는 달을 고른다. 기본값은 새 가입 규칙과 같다.
  - "탈퇴일은 탈퇴 상태에만 있다"를 쓰는 곳에서 지킨다. 그래서 탈퇴일을 읽는 곳이 상태를 다시 보지 않아도 맞다.
- **하지 않을 것**
  - 예전 회원 기간의 이력은 남기지 않는다 (사용자 결정 11-1: A).
    - 대가: 돌아온 회원의 지난 해 표에서 예전 기간이 해당없음(회색)으로 나오거나 줄이 빠진다.
  - 탈퇴한 사람이 앱에서 다시 가입 신청하는 길은 만들지 않는다. 지금처럼 관리자가 상태를 되돌린다.
- **실패로 볼 것**
  - 실수로 탈퇴 처리한 회원을 되돌렸는데 예전 시작월이 사라져 지난 달들이 해당없음이 되는 것.

## 4. 방법 (Approaches)

| 방법 | 모습 | 대가 | 결정 |
| --- | --- | --- | --- |
| 1. 상태를 바꿀 때 달을 묻기 | 탈퇴로 바꾸거나 탈퇴에서 되돌릴 때만 작은 시트가 뜨고, 기본값이 채워져 있다 | 상태 API와 회원 관리 화면을 고친다. 운영 중인 화면이라 배포 때 함께 바뀐다 | **고름** (사용자 11-2) |
| 2. 묻지 않고 서버가 기본값으로 넣기 | 화면은 그대로, 알림만 | 확인 없이 넘어가면 틀린 달이 남는다 | 버림 |
| 3. 회원 상세에 처리 버튼 따로 | [탈퇴 처리]·[다시 가입 처리] | 상태를 바꾸는 곳이 두 곳이 되고, 회원 관리에서 바꾸면 여전히 묻지 않는다 | 버림 |

## 5. 설계

### 5-1. 어떤 상태 변경에서 묻나

| 이전 → 다음 | 묻는 것 | 저장 |
| --- | --- | --- |
| 탈퇴 아님 → 탈퇴 | 탈퇴월 | `status = LEFT`, `leftAt = 그 달 1일 UTC` |
| 탈퇴 → 승인됨·휴가중 | 다시 시작하는 달 | `status`, `leftAt = null`, `feeObligationStartAt = 그 달 1일 UTC` |
| 그 밖 (승인됨 ↔ 휴가중, 탈퇴 → 거절됨 등) | 묻지 않음 | 지금처럼 상태만 바꾸고 `leftAt = null` |

- 달은 `YYYY-MM`로 주고받고, 저장은 그 달 1일 00:00 UTC다. 지금 시작월·탈퇴월과 같은 형식이다.

### 5-2. 기본값

- **탈퇴월: 그 회원의 마지막 납부 달.**
  - 납부(`MembershipPayment`) 중 연·월이 가장 늦은 것. 통장 입금 납부와 직접 추가 납부를 함께 본다.
  - 미리 낸 달이 있으면 그 달이 기본값이다(예: 12월까지 낸 회원은 12월).
  - 낸 회비가 없으면 비워 두고 "낸 회비가 없습니다." 안내를 보인다. 관리자가 고르기 전에는 [탈퇴 처리]가 눌리지 않는다.
- **다시 시작하는 달: 새 가입 규칙.**
  - 15일 이전이면 그 달, 이후면 다음 달. `join.ts`의 계산을 함수로 꺼내 둘이 함께 쓴다.
  - 시트에 예전 시작월을 함께 보인다: "실수로 탈퇴 처리했다면 예전 시작월(2024-03)을 고르세요."
    - 실패로 볼 것(3장)을 막는 장치다. 예전 시작월을 고르면 탈퇴 전과 같은 상태로 돌아간다.

### 5-3. API

- **`PUT /api/clubs/[id]/members/[userId]/status`** `{ status, leftMonth?, feeStartMonth? }`
  - 탈퇴로 바꿀 때 `leftMonth`가 없거나 형식이 틀리면 400 "탈퇴월을 골라주세요".
  - 탈퇴에서 승인됨·휴가중으로 바꿀 때 `feeStartMonth`가 없거나 형식이 틀리면 400 "다시 시작하는 달을 골라주세요".
  - 그 밖의 변경에서 두 값은 무시한다.
  - 이전 상태는 서버가 DB에서 읽어 판단한다 (화면이 보낸 이전 상태를 믿지 않는다).
- **`GET /api/clubs/[id]/members/[userId]/status-defaults`** (관리자)
  - `{ lastPaidMonth: 'YYYY-MM' | null, rejoinStartMonth: 'YYYY-MM', previousStartMonth: 'YYYY-MM' | null }`
- **`PATCH …/fee-obligation`이 같은 약속을 지킨다.**
  - 탈퇴가 아닌 회원에 `leftAt` 값을 보내면 400 "탈퇴한 회원만 탈퇴일을 넣을 수 있습니다". `null`은 받는다.
  - 탈퇴 회원의 `leftAt`을 `null`로 보내면 400 "탈퇴월을 입력해주세요".
  - 회원 상세 화면은 탈퇴 회원에게만 탈퇴일 칸을 보이므로 지금 쓰임새는 그대로 된다.
- **탈퇴일을 읽는 곳(매칭·확정 계획·이월)은 고치지 않는다.**
  - 위 두 API가 "탈퇴일은 탈퇴 상태에만 있다"를 지키고 운영 DB도 지금 그렇다.
  - 12번 때 미룬 `confirmPlanner`의 탈퇴일 문제도 이것으로 닫는다.

### 5-4. 화면 (회원 관리 시트)

```
회원 관리 › 홍길동 › 상태 [탈퇴 ▾]
┌ 탈퇴 처리 ─────────────────────┐
│ 탈퇴월   [2026-07]               │
│ 마지막으로 회비를 낸 달입니다.     │
│ 이 달까지 회비를 내야 하는 달로 봅니다. │
│            [취소]  [탈퇴 처리]     │
└────────────────────────────────┘

상태 [승인됨 ▾]  (탈퇴였던 회원)
┌ 다시 가입 처리 ───────────────────┐
│ 다시 시작하는 달   [2026-12]         │
│ 이 달부터 회비를 냅니다.             │
│ 실수로 탈퇴 처리했다면 예전 시작월(2024-03)을 고르세요. │
│            [취소]  [다시 가입 처리]   │
└────────────────────────────────┘
```

- 상태 고르기에서 5-1의 두 경우를 고르면 바로 저장하지 않고 시트를 연다. 기본값은 `status-defaults`로 채운다.
- [취소]하면 상태 고르기는 이전 값 그대로다.
- 저장하면 지금처럼 화면을 바꾸고, 실패하면 서버가 준 사유를 토스트로 보이고 되돌린다.
- 시트·달 입력·버튼은 기존 부품(`Sheet`, `FormField`, `Input type="month"`, `Button`)을 쓴다. 휴회 추가 시트와 같은 모양이다.

## 6. 확인

- 상태 API: 탈퇴 시 `leftMonth` 필수·저장값, 되돌릴 때 `feeStartMonth` 필수·`leftAt` 지움·시작월 저장, 그 밖의 변경은 지금과 같음, 권한.
- `status-defaults`: 마지막 납부(직접 추가 포함, 미리 낸 달), 납부 없음, 가입 규칙 15일 경계.
- `fee-obligation`: 탈퇴 아닌 회원의 탈퇴일 거절, 탈퇴 회원의 탈퇴일 지우기 거절, 기존 저장은 그대로.
- 회원 관리 화면: 두 경우에만 시트가 뜸, 기본값, 취소, 저장 요청 본문.
- `/dev/admin-preview?screen=members`를 휴대폰(390)·PC(1280), 라이트·다크로 본다.
- 배포 전에 운영 DB에서 "탈퇴인데 탈퇴일 없음"과 "탈퇴가 아닌데 탈퇴일 있음"이 0명인지 다시 본다. 운영(main)의 화면은 탈퇴일을 다루지 않아 배포 전까지 어긋난 회원이 새로 생길 수 있다.
