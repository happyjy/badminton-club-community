# 휴회 신청 설계

작성일: 2026-11-28
관련 화면: 내 회비(`/clubs/[id]/my-fee`)의 "휴회" 영역, 새 관리 화면 "휴회 신청"(`/clubs/[id]/membership-fee/leave-requests`), 회비 관리 대시보드, 클럽 설정(`/clubs/[id]/custom`)
먼저 할 작업: [회원별 납부 이력 (내 회비) 설계](./2026-11-28-my-fee-history-design.md) — 이 작업은 그 화면 위에 얹는다

## 1. 의도와 까닭

- **지금 휴회 신청은 회원이 카카오톡으로 재무님께 직접 보낸다.**
  - 재무님이 받은 내용을 회원 상세의 "휴회/병가 기간"에 손으로 넣는다.
  - 회원은 처리됐는지 알려면 다시 물어야 한다.
- **목표: 회원이 휴대폰에서 휴회를 신청하고, 임원이 앱에서 승인한다.**
  - 승인되면 휴회 기록이 생기고, 그 기간에 이미 낸 회비는 다음 의무월로 자동으로 넘어간다.
  - 회원은 "내 회비"에서 신청 상태와 결과를 본다.

## 2. 목표 · 하지 않을 것

| 구분 | 내용 |
| --- | --- |
| 목표 | 회원이 시작·끝 연월과 사유를 넣어 휴회를 신청한다. 한 번에 클럽이 정한 개월 수까지 |
| 목표 | 임원 누구나 승인·거절한다. 신청이 들어오면 임원 모두에게 메일이 간다 |
| 목표 | 승인하면 휴회 기록을 만들고, 그 기간의 납부를 다음 의무월로 넘긴다 |
| 목표 | 클럽 설정에서 "한 번에 신청할 수 있는 최대 개월 수"를 정한다. 기본 2 |
| 목표 | 내 회비에 회비 계좌와 "입금자명은 본인 실명으로" 안내를 보인다. 계좌는 클럽 설정에서 넣는다 (5.8) |
| 하지 않을 것 | 문자 알림. 나중에 더할 수 있게 알림을 한 함수로 모아 둔다 |
| 하지 않을 것 | 승인할 때 기간 고치기. 고쳐야 하면 승인 뒤 회원 상세의 휴회 수정으로 고친다 |
| 하지 않을 것 | 1년 동안 합친 휴회 개월 수 제한 |
| 하지 않을 것 | 회원 상태(`ClubMember.status`)를 "휴가중"으로 바꾸기. 휴회 기록과 회원 상태는 지금처럼 따로다 |
| 하지 않을 것 | 회원에게 결과 메일 보내기. 결과는 "내 회비"에서 본다 |
| 실패로 볼 것 | 승인 전 신청이 납부 현황·엑셀·카톡 이미지·미납 목록·입금 확정에 휴회로 계산되면 실패다 |
| 실패로 볼 것 | 승인이 그 신청 기간 밖의 납부를 옮기면 실패다 |

## 3. 사용자 결정 (2026-11-28)

- 재무님만이 아니라 임원(관리자) 권한이 있는 사람 누구나 승인한다.
- 시작월은 유동적이다. 회비를 안 낸 지난 달들을 휴회 기간으로 하고 싶을 수 있어 지난 달도 고를 수 있다.
- 휴회한 달에 이미 낸 회비는 기본적으로 다음 달로 넘긴다. 고칠 일이 있으면 재무님이 고친다.
- 신청할 때 끝나는 달을 꼭 정한다.
- 최대 개월 수는 클럽이 설정 화면에서 정한다. 당산클럽은 2개월이다.
  - **한 번 신청할 때 시작월부터 끝나는 달까지 합쳐 2달까지**다(예: 3월~4월). 1년 합산은 세지 않는다.
- 신청이 들어오면 임원 모두에게 메일로 알린다. 문자는 나중에 더할 수 있다.
- 만드는 방법은 아래 A(신청을 따로 저장).
- 내 회비의 입금 안내(회비 계좌·입금자명)를 이 작업에 넣는다 (2026-11-29). 계좌를 저장할 DB 칸이 필요해 이 작업의 마이그레이션에 묶는다.

## 4. 방법 (Approaches)

| 방법 | 모습 | 대가 | 결정 |
| --- | --- | --- | --- |
| A. 신청을 따로 저장 | 새 표 `LeaveRequest`. 승인하는 순간 지금의 `MemberLeave`를 만들고 납부를 이월 | 표가 하나 는다 | **고름** |
| B. `MemberLeave`에 상태 칸 더하기 | 휴회 기록 하나에 대기·승인·거절 | 휴회를 읽는 곳(`memberYearStatusLoader`, `confirmPlanner`, `unpaid`, 직접 추가 막기, 회원 상세 휴회 API, 비교 스크립트)이 모두 "승인된 것만" 걸러야 한다. 하나라도 빠지면 승인 전 신청이 휴회로 계산된다 | 버림 |

- A를 고른 까닭은 탈퇴월 작업과 같다. 읽는 곳은 그대로 두고 쓰는 곳에서 지킨다.

## 5. 설계

### 5.1 데이터 (DB 변경 있음)

```prisma
enum LeaveRequestStatus {
  PENDING   // 대기
  APPROVED  // 승인
  REJECTED  // 거절
  CANCELED  // 회원이 취소
}

model LeaveRequest {
  id            Int                @id @default(autoincrement())
  clubMemberId  Int
  startYear     Int
  startMonth    Int                // 1~12
  endYear       Int                // 꼭 있다 (MemberLeave와 다르다)
  endMonth      Int                // 1~12
  reason        String             // 50자까지
  status        LeaveRequestStatus @default(PENDING)
  createdAt     DateTime           @default(now())
  decidedById   Int?               // 승인·거절한 임원 (ClubMember)
  decidedAt     DateTime?          // 승인·거절·취소한 때
  rejectReason  String?            // 거절 사유, 100자까지
  memberLeaveId Int?     @unique   // 승인으로 만든 휴회. 휴회를 지우면 NULL

  clubMember  ClubMember   @relation(...)
  decidedBy   ClubMember?  @relation(...)
  memberLeave MemberLeave? @relation(fields: [memberLeaveId], references: [id], onDelete: SetNull)

  @@index([clubMemberId, status])
}
```

- **`ClubCustomSettings`에 두 칸을 더한다.**
  - `leaveRequestMaxMonths Int @default(2)` — 설정 행이 없는 클럽은 코드에서 2로 본다.
  - `feeBankAccount String?` — 회비 계좌 한 줄(예: "카카오뱅크 0000-00-0000000 예금주 OOO"). 대회의 `Tournament.bankAccount`와 같은 꼴이다. 없으면 입금 안내를 숨긴다.
- **스키마는 `prisma/schema/` 도메인 파일에 넣는다.**
  - 휴회 신청은 `memberLeave.prisma`에 둔다.
  - `schema.prisma`는 `npm run build:schema`로 만든다.
- **마이그레이션은 CLAUDE.md의 안전한 순서를 따른다.**
  - `migrate diff`에 이 변경 말고 다른 SQL이 섞이면 멈추고 알린다.
  - 적용 전에 사용자 확인을 받는다. `migrate dev`는 쓰지 않는다.

### 5.2 기간 규칙

| 규칙 | 실패 메시지 (400) |
| --- | --- |
| 시작 ≤ 끝 | "끝나는 달이 시작하는 달보다 빠릅니다" |
| 개월 수(시작·끝 포함) ≤ 클럽 최대 개월 수 | "한 번에 최대 N개월까지 신청할 수 있습니다" |
| 시작월 ≥ 회비 시작월(`feeObligationStartAt`, 한국 시각 연월). 시작월이 없으면 검사하지 않는다 | "회비를 내기 시작한 달보다 앞선 달은 신청할 수 없습니다" |
| 그 회원의 휴회 기록(`MemberLeave`, 끝 없는 휴회 포함)·대기 중인 신청과 한 달도 겹치지 않는다 | "이미 휴회 중이거나 신청한 달과 겹칩니다" |
| 회비 대상 아님 회원은 신청할 수 없다 | "회비 대상이 아닌 회원입니다" |

- 지난 달도 고를 수 있다(사용자 결정). 앞쪽 한계는 회비 시작월뿐이다.
- 면제 달·이미 낸 달이 들어 있어도 막지 않는다. 낸 달은 승인 때 이월한다.

### 5.3 API

모두 [API 핸들러 규칙](../../../.claude/rules/api-handler-conventions.md)의 응답 형식을 따른다.

| 메서드·경로 | 누가 | 하는 일 |
| --- | --- | --- |
| `GET /api/clubs/[id]/leave-requests/my` | 회원 본인 | `{ requests, maxMonths }`. requests는 대기 전부 + 거절된 것 |
| `GET /api/clubs/[id]/leave-requests/preview?start=YYYY-MM&end=YYYY-MM` | 회원 본인 | `{ months, paidCount, error }`. 기간 규칙을 미리 검사하고, 그 기간에 이미 낸 납부 건수를 센다. 저장하지 않는다 |
| `POST /api/clubs/[id]/leave-requests` | 회원 본인 | `{ start, end, reason }`. 회원 행을 잠그고(`SELECT … FOR UPDATE`) 기간 규칙을 다시 검사해 저장한 뒤 임원 알림을 보낸다 |
| `POST …/leave-requests/[requestId]/cancel` | 신청한 회원 본인 | 대기만 취소. `where`에 `status: PENDING`을 다시 건다 |
| `GET /api/clubs/[id]/leave-requests?status=pending\|decided` | 임원 | 목록. 회원 이름, 기간, 개월 수, 사유, 신청일, 상태, 그 기간의 납부 건수 |
| `POST …/leave-requests/[requestId]/approve` | 임원 | 아래 5.4 |
| `POST …/leave-requests/[requestId]/reject` | 임원 | `{ reason }`(필수, 100자). 대기만 거절 |

- **회원 본인 API는 `requireClubMember`로 막는다.** 신청은 그 클럽에서의 내 `ClubMember`에 묶인다. 다른 회원의 신청 id로 취소하면 404다.
- **임원 API는 `requireClubAdmin`(승인 상태 임원)으로 막는다.**
- **임원도 자기 휴회를 신청할 수 있고, 자기 신청을 직접 승인해도 된다.** (빌더 검토 반영, 내 판단)
  - 임원은 지금도 회원 상세에서 아무 회원(자기 포함)의 휴회를 직접 넣을 수 있어, 막아도 지켜지는 것이 없다.
  - 알림 메일은 신청한 본인을 빼고 보낸다.
- **성공 응답은 신청 저장도 HTTP 200·`status: 200`이다.** 프런트 훅이 `status !== 200`을 실패로 본다(API 규칙 3절).

### 5.4 승인

한 트랜잭션 안에서 한다.

1. 회원 행을 잠근다(입금 확정·직접 추가와 같다).
2. 신청이 대기가 아니면 400 "이미 처리된 신청입니다".
3. 그 회원의 휴회 기록과 겹치면 400 "이미 휴회로 등록된 달과 겹칩니다".
   - 신청 뒤에 임원이 회원 상세에서 직접 넣었을 수 있다.
   - 최대 개월 수는 다시 보지 않는다. 신청 뒤 설정이 바뀌어도 임원 판단으로 승인할 수 있다.
4. `MemberLeave`를 만든다(시작·끝·사유를 그대로 옮긴다).
5. **이 신청 기간 안의 납부만** 골라(`isMonthInLeave`) `planPaymentShifts`로 옮길 달을 정하고 연·월을 바꾼다.
   - 컨텍스트(`ShiftContext`)는 그 회원 한 명 것을 트랜잭션(`tx`) 안에서 읽어 만든다.
     - 시작월, 탈퇴일(탈퇴 상태일 때만), 새 휴회를 넣은 휴회 목록, 모든 납부, 면제가 들어간다.
     - `loadPlannerContext`는 클럽 전체를 읽고 트랜잭션을 받지 않아 쓰지 않는다. `payments/shift.ts`도 트랜잭션 밖에서 읽는다.
   - 기간 밖의 "의무 없는 달 납부"(예: 탈퇴 전 납부)는 건드리지 않는다.
6. 신청을 `APPROVED`로, `decidedById`·`decidedAt`·`memberLeaveId`를 채운다.

- **이월 계산(`paymentShift.ts`)의 두 구멍을 함께 고친다.** (빌더 검토 반영, 내 판단)
  - 회원 상세의 [다음 의무월로 이월](`payments/shift.ts`)도 같은 함수를 쓰므로 같이 바로잡힌다.
  - 같은 달의 납부 여러 건(부족분을 나중에 채운 경우)은 한 묶음으로 같은 달로 옮긴다.
    - 지금은 한 건씩 다음 미납월을 잡아, 한 달 몫이 두 달 낸 것으로 보인다.
  - 면제 달로는 옮기지 않는다.
    - 지금 `nextShiftTarget`은 면제를 보지 않는다. 면제 달로 옮겨지면 칸이 면제로 칠해져 낸 돈이 보이지 않는다.
    - `ShiftContext`에 회원별 면제 달을 더하고, `payments/shift.ts`도 면제를 읽어 넘긴다.
- 응답 `data`: `{ request, moved: [{ from, to, amount }], notMoved: [{ year, month, amount, reason }] }`.
- 화면은 `moved`만 있으면 토스트로 "승인했어요 · 낸 회비 2건을 2027년 2월·3월로 넘겼어요"를 띄운다.
- `notMoved`가 있으면 `hideCancel` 확인창으로 "넘기지 못한 납부 N건 — 회원 상세에서 확인해 주세요"와 사유를 보인다.
  - 사유 예: 탈퇴 회원이라 옮길 의무월이 없음.
- 승인 뒤 대시보드(`paymentDashboard`)와 내 회비(납부 이력) 캐시를 비운다.

### 5.5 임원 알림 (메일)

- **신청을 저장한 뒤 그 클럽의 임원(`role: ADMIN`, `status: APPROVED`) 모두의 `User.email`로 보낸다.** 신청한 사람이 임원이면 그 사람은 뺀다.
  - 카카오 로그인 때 받은 메일 주소다. 빈 값은 빼고 중복은 하나로 합친다.
  - 클럽 설정의 "이메일 수신자"(게스트 신청 메일용)는 쓰지 않는다(사용자 결정: 임원 모두).
- **보내는 방법은 `src/lib/email.ts`의 기존 Gmail 전송(nodemailer)을 쓴다.**
  - 템플릿은 `src/lib/email/templates/` 아래에 새로 둔다.
- **메일 내용**
  - 제목: "[클럽 이름] OOO님이 휴회를 신청했습니다"
  - 본문: 기간, 개월 수, 사유, 그 기간에 이미 낸 회비 건수, 관리 화면 링크(`getBaseUrl(req.headers.host)` + `/clubs/[id]/membership-fee/leave-requests`)
- **메일이 실패해도 신청은 성공이다.** 실패는 `console.error`로 남긴다.
- **나중에 문자를 더하기 쉽게 `notifyLeaveRequested(...)` 한 함수에서 보낸다.** 지금은 메일만 부른다.

### 5.6 화면 — 회원 (내 회비의 "휴회" 영역)

```
휴회                                    [휴회 신청]
  2026.12 ~ 2027.01 · 개인 사정     신청 중  ›
  2026.03 ~ 2026.04 · 병가          휴회
  2025.10 ~ 2025.11 · 부상          거절됨 · 증빙이 필요해요
```

- **줄은 대기 중인 신청 → 승인된 휴회 → 거절된 신청 순이다.**
  - 대기 신청은 연도와 상관없이 늘 보인다.
  - 휴회와 거절 신청은 고른 해와 겹치는 것만 보인다.
- **대기 줄을 누르면 시트가 열리고 [신청 취소]가 있다.**
  - 취소는 `useConfirm`으로 한 번 더 묻는다.
- **[휴회 신청] 시트**
  - 칸: 시작 연월(필수), 끝나는 연월(필수), 사유(필수, 50자, 예: 병가·출산·부상·개인 사정).
  - 안내: "한 번에 최대 N개월까지 신청할 수 있어요", "임원이 승인하면 휴회가 돼요".
  - 두 연월을 고르면 `preview`를 불러 규칙 위반을 칸 아래에 보이고, 이미 낸 달이 있으면 "이 기간에 낸 회비 N건은 승인되면 다음 달로 넘어가요"를 보인다.
  - 규칙을 지키고 세 칸이 다 차야 [신청]이 눌린다. 서버 실패 사유는 토스트로 보이고 시트를 열어 둔다.
- 회비 대상 아님 회원에게는 [휴회 신청]을 숨긴다.

### 5.7 화면 — 임원

- **새 화면 "휴회 신청"** (`/clubs/[id]/membership-fee/leave-requests`, 임원 전용)
  - 관리용 틀: `Toolbar` + `DataTable` + 상세 `Sheet`.
  - 보기: `SegmentedControl` "대기 / 처리됨".
  - 열: 회원, 기간(`2026.12 ~ 2027.01 · 2개월`), 사유, 신청일, 상태(`StatusChip`, 새 domain은 `statusTone.ts`에 더함).
  - 상세 시트: 내용, "이 기간에 낸 회비 N건(승인하면 다음 의무월로 넘김)", [승인]·[거절]. [거절]을 누르면 사유 칸이 나오고 사유가 있어야 확정된다. 처리됨이면 처리한 임원·때·거절 사유를 보인다.
- **회비 관리 대시보드**
  - 바로가기(`SHORTCUTS`)에 "휴회 신청"을 더한다.
  - 대기 신청이 있으면 대시보드 위쪽에 "대기 중인 휴회 신청 N건" 줄을 보이고, 누르면 이 화면으로 간다. 건수는 대시보드 API에 싣는다.
- **클럽 설정** (`/clubs/[id]/custom`)
  - "회비" 설정 묶음을 더한다. 칸은 두 개다. (묶음 이름은 내 판단 — 둘 다 회비 일이다)
    - "회비 계좌"(글, 100자까지, 비우면 안내를 숨김)
    - "휴회 신청 — 한 번에 신청할 수 있는 최대 개월 수"(정수 1~12, 기본 2)
  - 클럽 설정은 묶음마다 저장 API가 따로 있다(`src/pages/api/clubs/[id]/custom/` 아래 `home`·`guest-page`·`email`·`sms`·`parking`·`menu`). 같은 꼴로 하나를 더한다.
  - 회원의 신청 화면은 `GET …/leave-requests/my`의 `maxMonths`로 이 값을 받는다.
- **회원 상세에서 임원이 직접 넣는 휴회는 지금 그대로다.** 개월 수 제한도, 끝 없는 휴회도 그대로 된다.

### 5.8 입금 안내 (내 회비)

```
입금 안내
  카카오뱅크 0000-00-0000000 예금주 OOO      [복사]
  입금자명은 본인 실명으로 해 주세요.
  다른 사람 이름으로 냈다면 재무님께 알려 주세요.
```

- **까닭: 앱은 입금자명만으로 회원을 찾는다.**
  - 재무님이 통장 메모 없이 엑셀만 올리는 것이 목표라, 회원이 실명으로 입금해야 자동 매칭이 된다.
  - 다른 이름으로 낸 입금은 매칭되지 않아 "확인 중"에도 안 보이고 미납으로 남는다.
- **위치는 내 회비의 미납 요약 아래다.** 계좌가 비어 있으면 묶음 전체를 숨긴다.
- **[복사]는 계좌 글 전체를 클립보드에 넣고 토스트 "계좌를 복사했어요"를 띄운다.**
  - 휴대폰 은행 앱에 붙여 넣기 쉽게 하려는 것이다.
- **회원에게 보이는 안내 문구는 초안이다.** 사용자가 바꿀 수 있다.
- **계좌는 `GET /api/clubs/[id]/members/[userId]/fee-history` 응답에 `feeBankAccount`로 싣는다.**
  - 내 회비가 이미 부르는 API라 요청이 늘지 않는다.
  - 회원 상세(임원)에서는 안내 묶음을 그리지 않는다.

## 6. 제약

- **로컬 dev 서버도 운영 DB와 실제 Gmail을 쓴다.**
  - 로컬에서 신청을 만들면 운영 DB에 저장되고 실제 임원에게 메일이 간다.
  - 확인은 jest(메모리 DB, 메일 전송 mock)와 `/dev` 미리보기의 가짜 데이터로 한다.
  - 실제로 눌러 보는 확인이 필요하면 사용자에게 먼저 묻는다.
- **DB 변경은 사용자 확인 뒤에 적용한다.** (5.1)
- **문서·미리보기·테스트에 실명을 쓰지 않는다.** (공개 저장소)
- 디자인 시스템 규칙, 지킴이 테스트, 테스트 파일 위치 규칙을 따른다.
- 원시 `<input>`·`confirm()`을 쓰지 않는다. 확인은 `useConfirm`, 결과는 토스트다.

## 7. 검증

- **기간 규칙**: 5.2의 다섯 경우를 신청 API·preview API 각각에서 확인한다. 끝 없는 휴회와의 겹침, 해를 넘는 기간(12월~1월) 개월 수 계산도 본다.
- **승인**
  - 휴회 기록이 생기고, 기간 안의 납부만 다음 의무월로 옮겨진다.
  - 기간 밖의 의무 없는 납부는 그대로다.
  - 옮길 달이 없으면 `notMoved`로 나온다.
  - 같은 달 두 건은 같은 달로 함께 옮겨진다. 면제 달은 건너뛴다(회원 상세의 이월 버튼도 같다).
  - 이미 처리된 신청과 겹침은 400이다.
  - 두 임원이 동시에 승인해도 한 번만 처리된다.
- **승인 전 신청은 계산에 안 들어간다**: 대기 신청이 있어도 대시보드 `cells`, 미납 목록, 입금 확정 계획이 바뀌지 않는다.
- **권한**
  - 회원은 남의 신청을 취소할 수 없다.
  - 회원은 승인·거절·임원 목록을 쓸 수 없다.
  - 휴가중 임원은 승인할 수 없다(`requireClubAdmin`).
- **알림**: 임원 모두에게 한 통씩 가고(신청한 임원 본인은 뺌), 메일이 실패해도 신청은 200으로 성공한다.
- **입금 안내**: 계좌가 있으면 보이고 없으면 숨는다. 클럽 설정에서 저장·비우기가 된다. 회원 상세에는 안 나온다.
- **화면**: 내 회비 휴회 영역, 신청 시트, 임원 화면·시트를 미리보기로 휴대폰·PC, 라이트·다크 네 가지로 본다.
