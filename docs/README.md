# docs

문서는 **성격별로** 폴더를 나눈다. 파일명에는 종류를 넣지 않는다. 폴더가 그 역할을 한다.

| 폴더           | 담는 것                                                |
| -------------- | ------------------------------------------------------ |
| `pr/`          | PR 본문. 배경, 작업 내용, 검증, 체크리스트             |
| `기획/`        | 기능별 기획서. 기능 단위로 하위 폴더를 둔다            |
| `리뷰/`        | 코드 리뷰 기록                                         |
| `블로그/`      | 외부 공개용 기술 글                                    |
| `검토/`        | 특정 주제 조사·검토 결과                               |
| `가이드/`      | 상시 참고하는 작업 규칙                                |
| `노트/`        | 개인 메모, todo                                        |
| `양식/`        | 외부에 전달하는 서식                                   |
| `superpowers/` | 스킬이 생성하는 `plans/`, `specs/`. 직접 만들지 않는다 |

## 새 문서를 둘 위치

PR을 올리는 작업이면 `pr/`에 둔다. 파일명은 작업 내용만 적는다
(`인증번호-미발송-수정.md`). 기존 문서의 구성을 따르면 PR 본문으로 그대로 쓸 수 있다.

기능을 새로 만들 때의 기획서는 `기획/<기능 이름>/`에 둔다. 기능 폴더가 없으면
만든다.

어디에 둘지 애매하면 `노트/`에 두고 나중에 옮긴다. 분류를 고민하다 기록을 남기지
않는 것이 더 손해다.
