# `/membership-fee` 대시보드 + 삭제→재업로드 흐름 검토 (2026-05-25)

회원별 납부 현황 테이블이 잘 보이는지, 그리고 업로드 이력에서 batch를 삭제하고 같은 파일을 재업로드하는 흐름에서 발생할 수 있는 함정을 정리한다. 직접 테스트 전 미리 확인할 시나리오로 활용한다.

검토 범위는 `/clubs/[id]/membership-fee` 대시보드 화면, `PaymentDashboardTable`, `dashboard.ts` API, `batches/[batchId].ts` 삭제 API, `upload.ts` 재업로드 동작에 한정한다. 전반 검토는 [`재무-사용성-검토-2026-05-25.md`](./재무-사용성-검토-2026-05-25.md) 참고.

---

## P0 — 삭제·재업로드에서 데이터가 어긋날 수 있는 곳

### 1. batch 삭제 시 확정 건도 경고 없이 cascade 삭제됨

- **시나리오**: 50건 중 30건 확정된 batch를 삭제 → 확정된 30건의 `MembershipPayment`까지 같이 날아감.
- **위치**: `src/pages/api/clubs/[id]/membership-fee/batches/[batchId].ts:66` — `paymentUploadBatch.delete()` 한 줄로 prisma cascade가 record + membershipPayment까지 다 지움. **API 단에 확정 건 확인 로직이 전혀 없음.**
- **결과**: 대시보드 회원별 납부 현황의 ✓가 갑자기 X로 바뀜. 재무는 "왜 갑자기 미납으로 보이지?" 당황.
- **재무가 알아챌까**: process 화면 안의 삭제 모달은 경고를 주지만, **업로드 이력(`batches.tsx`) 페이지엔 삭제 버튼이 BatchRow에 없고**, batchId 페이지 진입 후 process 화면을 통해서만 삭제 가능. 즉 process 경고가 유일한 안전망인데, API에는 이중 가드 없음.
- **테스트 전 권장**: 확정된 건이 있는 batch는 삭제하지 말 것. 또는 process 화면에서 확정 상태를 먼저 일괄 미확정.

### 2. 재업로드 시 같은 입금 건 중복 가능성

- **시나리오**: 같은 엑셀을 두 번 업로드. 또는 일부만 처리하다 batch 삭제 후 같은 파일 재업로드.
- **위치 확인 필요**: `upload.ts`에 중복 검출 로직(같은 transactionDate + amount + depositorName 조합)이 있는지 확실치 않음.
- **결과**: 같은 입금이 두 record로 매칭·확정되면 `MembershipPayment`에 (clubMemberId, year, month) unique 제약이 없는 경우 월 합계가 두 배.
- **테스트 전 확인할 것**: 재업로드 직후 대시보드의 월 금액(amountsByMonth)이 부풀어 있는지.

## P1 — 회원별 납부 테이블이 가독성·정확성을 잃는 지점

### 3. 부부 회원이 두 row로 표시되면서 합계가 헷갈릴 수 있음

- **시나리오**: 부부 합산 입금 45,000원이 확정되면 `MembershipPayment`가 두 회원에게 각각 생성. 테이블에 두 row가 따로 보이고 둘 다 ✓.
- **위치**: `src/pages/api/clubs/[id]/membership-fee/dashboard.ts:209-317` — "부부도 개인 row로 산출" 주석 있음. `amountsByMonth`는 모든 payment 합산(라인 205-207).
- **결과**: 월별 통계의 `amount`가 부부 합산을 어떻게 분배하느냐에 따라 사용자에게 헷갈림. 예상이 "월 합계 45,000"인데 22,500 × 2 = 45,000으로 떨어진다면 OK, 각자 45,000으로 들어가면 두 배.
- **테스트 전 확인할 것**: 부부 확정 후 대시보드 우측 상단의 "월 합계" vs 실제 입금 합계 비교.

### 4. 부부 한쪽 탈퇴/이혼 후 partnerName이 stale하게 남아있을 수 있음

- **시나리오**: 부부 A-B 중 B가 탈퇴. `coupleGroup.members`에 B가 여전히 있으면 A row 하단에 "(B 이름)" 그대로 표시.
- **위치**: `dashboard.ts:216-219` — `coupleGroup.members.find(m !== member.id)`로 partner를 뽑음. coupleGroup이 동기화되지 않으면 stale.
- **결과**: 재무가 "이 사람 부부 맞나? 배우자 탈퇴 안 했나?" 혼란.
- **테스트 전 확인할 것**: 부부 중 한 명을 탈퇴 처리한 뒤 대시보드 표시 확인.

### 5. throughMonth 필터에서 휴회 회원이 "납부 완료"로 잘못 분류될 수 있음

- **시나리오**: 회원 X가 5월 전체가 휴회. 5월까지 throughMonth로 "납부 완료" 필터 → `obligationMonths`에 5월 없으니 통과. 사용자 입장에선 "5월에 휴회 중인 사람이 왜 납부 완료에 보여?".
- **위치**: `src/components/organisms/membership-fee/PaymentDashboardTable.tsx:59-73` `memberFullyPaidThroughMonth` — `obligationMonths.filter(m <= throughMonth).every(paid)`. 의무 0건이면 `every` → true.
- **결과**: 휴회 전체 기간인 회원이 "납부 완료" 탭에 표시될 가능성.
- **테스트 전 확인할 것**: 휴회 회원을 만들어 두고 "납부 완료" 탭에서 어떻게 보이는지.

### 6. 미래 월 셀 표시가 빈칸이라 모호

- **위치**: `PaymentDashboardTable.tsx:212-216` `showRedX` — `isPastOrCurrentMonth && !isPaid`. 미래 월은 빈 칸/✗ 안 나옴.
- **결과**: 올해 12월에 1~12월 보면 X가 많이 보이고, 6월에 1~12월 보면 7~12는 비어 있어 "왜 없지?" 헷갈림. 의도된 동작이지만 시각적 안내(예: 미래 월은 회색 음영)가 없음.
- **테스트 전 확인할 것**: 연도를 미래로 바꿔서(2027) 봤을 때 모든 셀이 어떻게 그려지는지 — 빈 칸뿐이면 OK, 모두 X면 버그.

## P2 — 테스트 동선 가이드

### 7. 업로드 이력 페이지에서 직접 삭제할 수 없음

- **위치**: `src/pages/clubs/[id]/membership-fee/batches.tsx:59-125` `BatchRow`에 삭제 버튼 없음. process 페이지로 들어가야만 삭제 가능.
- **테스트할 때**: "업로드 이력에서 지우고 다시 올린다"는 정확히는 **업로드 이력 → batch 클릭 → process 화면 → 삭제** 동선. 추가 클릭 1번 더.

### 8. 대시보드 캐시가 batch 삭제 후 자동 갱신되는지

- **위치**: `usePaymentDashboard` 훅이 batch 삭제 mutation 후 invalidate 되는지 확인 필요.
- **테스트할 때**: 삭제 직후 대시보드 페이지로 이동했을 때 stale 표시면 강제 새로고침(F5)으로 확인.

## 직접 테스트 전 권장 시나리오

| 우선순위 | 시나리오                                                        | 보는 곳                                  |
| -------- | --------------------------------------------------------------- | ---------------------------------------- |
| P0       | 확정 30건/총 50건 batch 삭제 → 대시보드 ✓이 X로 바뀌는지        | 회원별 납부 현황 테이블                  |
| P0       | 같은 엑셀 두 번 업로드 → 중복 record 생성되는지                  | process 페이지 record 개수, 대시보드 월 합계 |
| P0       | batch 삭제 → 같은 파일 재업로드 → 처리 결과 동일한지            | record/매칭 상태 비교                    |
| P1       | 부부 확정 후 대시보드 월 합계                                    | 합계가 두 배 아닌지                      |
| P1       | 부부 한쪽 탈퇴 처리 후 partner 이름 표시                         | A row 하단 "(B)" 잔존 여부               |
| P1       | 휴회 회원 "납부 완료" 탭 노출 여부                               | throughMonth 필터                        |
| P2       | 미래 연도(2027)로 전환 시 셀 표시                                | 모두 빈칸인지, X가 떠 있지 않은지        |

**테스트 직전 조치 권장**: 확정 상태인 record가 있는 batch는 **process에서 먼저 일괄 미확정 후 batch 삭제**. 이렇게 하면 1번 함정을 피하면서 깨끗한 재업로드 테스트 가능.
