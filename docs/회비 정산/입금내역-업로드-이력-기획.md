# 입금 내역 업로드 이력 관리 기획

## 1. 배경 (Why)

관리자는 카카오뱅크에서 입금 내역을 엑셀로 다운로드해서 주기적으로 업로드한다. 그러나 **"어디까지 업로드했는지"** 를 잊어버리기 쉬워, 다음 업로드 시 어느 시점부터 엑셀을 다시 받아야 할지 매번 확인해야 하는 불편이 있다.

→ 가장 최근에 어디까지 반영됐는지 **한눈에** 보여주는 장치가 필요하다.

---

## 2. 목표

1. 회비 대시보드 진입 즉시 "가장 최근에 반영된 거래일"을 확인할 수 있다.
2. 과거 업로드 이력을 필요 시 조회할 수 있다. (Phase 2)
3. 잘못 올린 엑셀을 삭제하는 기능은 **제공하지 않는다**. (필요 시 별도 논의)

---

## 3. 현재 상태 분석

### 3.1 이미 존재하는 것

- `PaymentUploadBatch` 모델 (`prisma/schema/membershipFee.prisma:123`)
  - 필드: `id`, `clubId`, `uploadedAt`, `uploadedById`, `fileName`, `recordCount`
  - 업로드 API(`src/pages/api/clubs/[id]/membership-fee/upload.ts:169`)에서 업로드 시마다 이미 생성 중.
- `PaymentRecord.transactionDate`
  - 엑셀에서 파싱한 실제 거래 일시가 저장되어 있음.
- `PaymentRecord` 조회 API(`src/pages/api/clubs/[id]/membership-fee/records/index.ts:70-72`)
  - 이미 `batch: { id, fileName, uploadedAt }` 를 include 중.

### 3.2 빠진 것

- **회비 대시보드 API** (`dashboard.ts`)가 배치 정보를 반환하지 않음.
- **회비 대시보드 UI**에 "마지막 업로드" 인디케이터가 없음.
- 업로드 이력을 한번에 볼 수 있는 목록 페이지가 없음.

---

## 4. 핵심 결정사항

| 항목        | 결정                                                                         |
| ----------- | ---------------------------------------------------------------------------- |
| 강조할 기준 | **최신 거래일 (max(PaymentRecord.transactionDate))** — "어디까지 커버됐는가" |
| 보조 정보   | 마지막 업로드 시점 (uploadedAt), 파일명, 업로더, 건수                        |
| 배너 위치   | 회비 대시보드 **상단에 큰 카드**                                             |
| 경고 스타일 | 최신 거래일이 오래 지났으면 주황색 강조 (기준: 추후 조정)                    |
| 배치 삭제   | **제외** (잘못 올린 엑셀 롤백 기능은 당장 불필요)                            |
| 진행 방식   | Phase 1 먼저 → 커밋 → Phase 2 (이력 목록 페이지)                             |

### 4.1 "어디까지"의 두 해석

대시보드에는 **둘 다** 표시하되, 최신 거래일을 크게 강조한다.

1. **거래일 기준** (강조) — `max(PaymentRecord.transactionDate)`
   - 다음 엑셀을 어느 시점부터 받아야 할지 바로 알 수 있는 핵심 지표.
2. **업로드 시점 기준** (보조) — `PaymentUploadBatch.uploadedAt` (최신 1건)
   - "마지막으로 시스템에 반영한 시점"을 알려주는 감사(audit)용 정보.

## 5. Phase 1 — 대시보드 상단에 "마지막 업로드" 카드 (MVP)

### 5.1 API 확장

**파일**: `src/pages/api/clubs/[id]/membership-fee/dashboard.ts`

**응답 `data` 에 추가**:

```ts
latestUpload: {
  lastBatch: {
    id: string;
    uploadedAt: Date;
    fileName: string;
    recordCount: number;
    uploadedByName: string | null;
  } | null;
  latestTransactionDate: Date | null; // 전체 배치 통틀어 max(transactionDate)
}
```

**추가 쿼리 2개** (연도 필터 없이 클럽 전체 기준):

```ts
// 최신 배치 1건
const lastBatch = await prisma.paymentUploadBatch.findFirst({
  where: { clubId: clubIdNumber },
  orderBy: { uploadedAt: 'desc' },
  include: { uploadedBy: { select: { name: true } } },
});

// 반영된 입금 중 가장 최근 거래일
const latestTx = await prisma.paymentRecord.aggregate({
  where: { clubId: clubIdNumber },
  _max: { transactionDate: true },
});
```

### 5.2 훅/타입

**파일**: `src/hooks/membership-fee/usePaymentDashboard.ts` (및 관련 타입)

### 5.3 UI 카드

**위치**: 페이지 헤더 아래, "빠른 링크" 그리드 **위**.

- 최신 거래일이 오래 지남: 주황색 경고 강조 + "입금 내역 업로드가 필요할 수 있습니다" 문구.

## 6. Phase 2 — 업로드 이력 목록 페이지 (차기 커밋)

### 6.1 신설 API

**파일**: `src/pages/api/clubs/[id]/membership-fee/batches/index.ts` (GET)

**응답**:

```ts
batches: Array<{
  id: string;
  uploadedAt: Date;
  fileName: string;
  uploadedByName: string | null;
  recordCount: number;
  minTransactionDate: Date | null;
  maxTransactionDate: Date | null;
  stats: {
    pending: number;
    matched: number;
    confirmed: number;
    error: number;
    skipped: number;
  };
}>;
```

- 정렬: `uploadedAt desc`
- 각 배치별 집계는 `groupBy` 또는 배치당 `_count` 쿼리로.

### 6.2 UI 페이지

**파일**: `src/pages/clubs/[id]/membership-fee/batches.tsx`

**테이블 컬럼**:

| 업로드일시 | 파일명 | 업로더 | 거래일 범위 | 총건수 | 매칭 / 확정 / 오류 |

**동작**:

- 각 행 클릭 → `/clubs/[id]/membership-fee/process?batchId=xxx` 로 이동 (기존 `records/index.ts` 가 이미 `batchId` 쿼리를 지원)
- 회비 대시보드의 빠른 링크 영역에 **"업로드 이력"** 링크 추가

### 6.3 배치 삭제 — 제외

당장 불필요. 필요해지면 별도 기획으로 분리. (고려사항: 확정된 `MembershipPayment`가 있는 배치는 삭제 금지 가드 필요)

## 7. Phase 2.5 — 배치 삭제 (중복 업로드 대응)

### 7.1 배경

같은 엑셀 파일을 실수로 2번 올리는 케이스가 발생할 수 있다. 업로드 이력 페이지에서 잘못 올린 배치를 찾아 삭제하는 방식으로 대응한다.

### 7.2 핵심 결정사항

| 항목                  | 결정                                                               |
| --------------------- | ------------------------------------------------------------------ |
| 확정 건이 있는 배치   | **삭제 허용** (차단하지 않음) — 사용자가 확정 건을 따로 찾아 취소하는 번거로움 제거 |
| 안전장치              | 삭제 확인 모달에서 확정 건 수를 명확히 경고                        |
| 삭제 범위             | 배치 + 하위 PaymentRecord + 관련 MembershipPayment cascade 삭제    |
| 진입 경로             | 업로드 이력 → 배치 클릭 → 입금 내역 처리(해당 배치만 필터) → 삭제  |

### 7.3 작업 내용

#### 7.3.1 process.tsx에 batchId 필터 연동

**파일**: `src/pages/clubs/[id]/membership-fee/process.tsx`

- URL의 `?batchId=xxx` 쿼리를 읽어서 `usePaymentRecords`에 전달 (훅은 이미 `batchId` 파라미터 지원)
- 배치 필터 중일 때 헤더에 배치 정보(파일명 등) 표시 + "배치 삭제" 버튼 노출

#### 7.3.2 배치 삭제 API

**파일**: `src/pages/api/clubs/[id]/membership-fee/batches/[batchId].ts` (신설)

- `DELETE` 메서드
- 삭제 전 확정 건 수 조회 → 프론트에서 확인 모달 분기용으로 활용
- 배치 + 하위 `PaymentRecord` + 관련 `MembershipPayment` cascade 삭제
- ADMIN 권한 확인

#### 7.3.3 삭제 확인 모달

- 확정 건 **0건**: "이 배치(42건)를 삭제하시겠습니까?"
- 확정 건 **있음**: "이 배치에 **확정된 납부 N건**이 포함되어 있습니다. 삭제하면 해당 납부 내역도 함께 삭제됩니다. 정말 삭제하시겠습니까?" (빨간색 경고)

### 7.4 수정/신설 파일 목록

1. `src/pages/clubs/[id]/membership-fee/process.tsx` — batchId 쿼리 연동, 배치 헤더, 삭제 버튼
2. `src/pages/api/clubs/[id]/membership-fee/batches/[batchId].ts` — 배치 삭제 API (신설)
3. 삭제 확인 모달 컴포넌트 (process.tsx 내부 또는 별도 분리)

## 8. Phase 3 — 사용성 보강 (선택)

- **업로드 화면 안내**: `upload.tsx` 진입 시 "마지막으로 반영된 거래일: 2026-04-05" 표시 → 엑셀 받을 시점 바로 파악 가능.
- **중복 감지**: 동일한 `transactionDate + amount + depositorName` 조합이 이미 있으면 업로드 시 경고 (재업로드 방지).
