# 입금 내역 처리

> 화면: `/clubs/[id]/membership-fee/process`
> 소스: `src/pages/clubs/[id]/membership-fee/process.tsx`, `src/components/organisms/membership-fee/PaymentRecordTable.tsx`

이 폴더는 입금 내역 처리 화면 한 단위의 문서를 모은다.

## 어디부터 읽을까

- **이 화면이 처음**이라면 → [입금내역-처리-컨텍스트.md](./입금내역-처리-컨텍스트.md)
  화면 전체의 현재 모습(아키텍처·구현 완료 기능·핵심 플로우·데이터 모델·부족/초과 처리)을 한 페이지로 요약한 화면 단위 문서. 항상 최신 상태로 유지된다.
- **특정 기능이 왜 이렇게 됐는지** 알고 싶다면 → [`기능/`](./기능/)
  개별 변경의 배경(Why), 설계 의사결정, 도입 이력을 남기는 기능 단위 문서들. 한 번 작성된 후엔 갱신하지 않거나, 후속 결정으로 덮어쓴다.

## 문서 구조 원칙

| 구분 | 역할 | 갱신 정책 |
| --- | --- | --- |
| 화면 컨텍스트 (`입금내역-처리-컨텍스트.md`) | 지금의 모습 — 아키텍처·기능 매핑·플로우 | 변경마다 갱신 |
| 기능 단위 (`기능/*.md`) | 왜·어떻게 그 결정이 됐는지 — 배경·의사결정·이력 | 시점 기록, 후속 변경은 새 문서로 누적 |

> 기능 문서를 추가하면 **컨텍스트 문서의 관련 섹션도 함께 갱신**하고, 컨텍스트 문서에서 그 기능 문서로 가는 링크를 걸어둔다. 두 문서가 양방향으로 연결되어 있어야 화면 단위 진입과 기능 단위 추적이 모두 가능해진다.
