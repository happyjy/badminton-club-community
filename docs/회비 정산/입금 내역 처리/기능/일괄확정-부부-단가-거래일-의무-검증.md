# 일괄 확정 부부 단가 — 거래일 배우자 의무 검증

작성일: 2026-05-11
관련 화면: `/clubs/[id]/membership-fee/process` (입금 처리 — 매칭된 항목 일괄 확정)
관련 파일:

- `src/lib/membership-fee/coupleRateResolver.ts` (신설)
- `src/lib/membership-fee/coupleRateResolver.test.ts` (신설)
- `src/pages/api/clubs/[id]/membership-fee/records/bulk-confirm.ts` (인라인 단가 판정을 모듈 호출로 교체)

## 1. 배경 (Why)

### 운영 사고

부부 회원 관리에서 "김가온(가입자) ↔ 이나래(2026-05 가입)" 부부 이력을 등록한 뒤 김가온의 1~4월(이나래 가입 전) 입금 내역 5건을 일괄 확정하려 하자 모두 "입금 부족" 사유로 실패했다.

```
{ "recordId": "...", "reason": "입금 부족 (25,000원) - 개별 확정에서 월 선택 후 부족 확정해주세요" }
```

일반 단가가 25,000원/월인데도 "부족"으로 떨어진 점이 단서였다.

### 원인

`bulk-confirm.ts`의 단가 판정에는 두 분기가 있었다.

```ts
const isFullCoupleMatch =
  effectiveCoupleMemberIds.length > 0 &&
  effectiveCoupleMemberIds.length === memberIds.length &&
  effectiveCoupleMemberIds.every((id) => memberIdSet.has(id));

if (isFullCoupleMatch) {
  totalPerMonth = feeSettings.coupleAmount; // 세대당 45,000원
  ...
} else {
  amountPerMemberPerMonth = memberIds.map((mid) => {
    const inHistory = wasCoupleAt(mid, txDate, coupleHistories).isCouple;
    const inGroup = findCoupleGroup(mid, coupleGroups) != null;
    return inHistory || inGroup
      ? feeSettings.coupleAmount        // 45,000
      : feeSettings.regularAmount;      // 25,000
  });
}
```

두 곳 모두 "거래일에 배우자도 의무인지"를 충분히 검증하지 않았다.

| 분기 | 문제 |
| --- | --- |
| 풀매치(`isFullCoupleMatch`) | 부부 후보 2명 중 한쪽이 의무가 아니어서 `effective`가 1명만 남고, 매칭된 인원도 그 1명이면 풀매치가 **잘못 발동**해 세대 단가 45,000원이 1인분에 그대로 적용됨 |
| 폴백(회원별 단가) | `inGroup`만 true여도(=현재 부부 그룹 소속) 부부 단가 적용. 거래일에 배우자가 미가입/탈퇴/장기 휴회여도 구분 못 함 |

이나래 가입 전(2026-01~04) 김가온 단독 입금 25,000원의 경우:

1. CoupleHistory `startedAt = 2026-05-01` → 거래일이 그 이전이라 `wasCoupleAt = false`
2. 그러나 CoupleGroup은 동기화로 이미 생성되어 있고, `findCoupleGroup` fallback으로 후보 [김가온, 이나래] 잡힘
3. 이나래는 거래일에 미가입이라 `effective = [김가온]` (1명)
4. **풀매치 조건이 통과** (effective 1명 = memberIds 1명) → 세대 단가 45,000원이 김가온 1명에게 적용
5. 25,000 % 45,000 ≠ 0 → "입금 부족"

## 2. 도입한 개선

### 2-1. 단가 판정 로직 모듈 추출

핸들러 안에 인라인으로 있던 단가 판정 블록을 `src/lib/membership-fee/coupleRateResolver.ts`로 분리해 단위 테스트 가능하게 만들었다. 서명:

```ts
resolveMonthlyAmount(params: {
  memberIds: number[];
  txDate: Date;
  coupleHistories: CoupleHistoryRow[];
  coupleGroups: CoupleGroupForRate[];
  memberStartAtMap: Map<number, Date | null>;
  memberLeftAtMap: Map<number, Date | null>;
  leaveMap: Map<number, LeavePeriod[]>;
  feeSettings: { regularAmount: number; coupleAmount: number };
}): {
  amountPerMemberPerMonth: number[];
  totalPerMonth: number;
  isFullCoupleMatch: boolean;
}
```

### 2-2. 풀매치 조건 강화 — "후보 2명 이상 + 후보 전원 의무"

```ts
const isFullCoupleMatch =
  coupleCandidateIds.length >= 2 &&                                  // 추가
  effectiveCoupleMemberIds.length === coupleCandidateIds.length &&   // 추가
  effectiveCoupleMemberIds.length === memberIds.length &&
  effectiveCoupleMemberIds.every((id) => memberIdSet.has(id));
```

후보가 1명만 남으면(=배우자 미가입/탈퇴/휴회) 풀매치가 발동하지 않아 세대 단가가 1인분에 잘못 적용되지 않는다.

### 2-3. 폴백에서도 거래일 배우자 의무를 본다

```ts
const amountPerMemberPerMonth = memberIds.map((mid) => {
  const historyAt = wasCoupleAt(mid, txDate, coupleHistories);
  if (historyAt.isCouple) return feeSettings.coupleAmount;

  const groupMembers = findCoupleGroupMembers(mid, coupleGroups);
  const groupPartnerObligated = groupMembers
    .filter((id) => id !== mid)
    .some((id) => isObligatedAtTx(id));
  if (groupPartnerObligated && isObligatedAtTx(mid)) {
    return feeSettings.coupleAmount;
  }
  return feeSettings.regularAmount;
});
```

`inHistory`(거래일 active row)면 그 시점 부부가 확정이라 부부 단가. 아니면 group을 fallback으로 보되, **그룹의 다른 멤버가 거래일에 의무**여야 부부 단가. 그 외에는 일반 단가.

### 2-4. 운영자 명시 매칭 신뢰 (D안)

후속 사고: 4월 29일에 5월 부부 회비 45,000원을 미리 입금한 record가 일괄 확정에서 또 실패했다. 사유는 "입금 부족 (45,000원)". 거래일 시점에 이나래(5월 가입)가 아직 의무가 아니라 풀매치가 깨지고, 폴백에서 두 명 각각 일반 단가 25,000이 적용되어 합계 50,000이 됐기 때문.

문제는 이게 명백한 부부 입금이라는 점이다 — 운영자가 김가온·이나래 두 명을 명시적으로 매칭했고, 부부 이력도 시스템에 등록되어 있다. 거래일 의무 검증을 그대로 강제하면 "5월 회비 사전 입금" 같은 정상 운영 케이스가 일괄 확정에서 매번 빠진다.

D안: **운영자가 부부 두 명을 직접 매칭한 record는 거래일 의무 검증을 우회**하고 풀매치 부부 단가로 인정.

```ts
const isOperatorAssertedCouple =
  !isFullCoupleMatch &&
  memberIds.length === 2 &&                          // 1인 매칭에는 절대 진입 X
  isKnownCouplePair(
    memberIds[0],
    memberIds[1],
    coupleHistories,
    coupleGroups
  );

if (isFullCoupleMatch || isOperatorAssertedCouple) {
  // 세대 단가 균등 분배 (기존 풀매치 분기와 동일)
  ...
}
```

발동 조건 두 신호:

1. **운영자가 두 명을 직접 매칭** (`memberIds.length === 2`)
2. **그 둘이 부부 이력 또는 부부 그룹에 한 쌍으로 등록** (`isKnownCouplePair`)

`isKnownCouplePair`는 `CoupleHistory`의 active/closed/future 무관하게 동일 쌍 row가 있는지, 또는 두 명짜리 `CoupleGroup`이 그 두 ID로 구성되어 있는지를 본다. 운영자가 부부 관계를 시스템에 명시한 적이 있다는 신호로 충분하다.

**1인 매칭은 절대 진입하지 않으므로** 이전 사고("이나래 가입 전 김가온 단독 25,000원 입금")는 이 분기에 영향받지 않는다 — 그 record는 매칭 인원이 1명이라 D안 가드(`memberIds.length === 2`)에서 막힌다.

### 2-5. 핸들러는 호출만

`bulk-confirm.ts`는 텅 빈 자리에 모듈 호출 한 줄만 남겨 흐름이 짧아졌다.

```ts
const txDate = new Date(record.transactionDate);
const { amountPerMemberPerMonth, totalPerMonth } = resolveMonthlyAmount({
  memberIds, txDate,
  coupleHistories, coupleGroups,
  memberStartAtMap, memberLeftAtMap, leaveMap,
  feeSettings,
});
```

## 3. 의사결정

| 결정 | 이유 |
| --- | --- |
| 풀매치에 "후보 2명 이상" 명시 | 후보가 1명이면 그건 본질적으로 "단독 매칭"이지 부부 매칭이 아니다. 명시하지 않으면 세대 단가가 1인분에 잘못 적용 |
| 폴백에서 `inGroup` 단독으로는 부부 단가 안 매김 | `CoupleGroup`은 "현재 시점" 데이터라 거래일 시점 부부 여부를 보증하지 못한다. 거래일 기준 의무인 배우자가 있을 때만 부부 세대 입금으로 본다 |
| 거래일 의무 풀매치 외에 D안(운영자 명시 매칭 신뢰) 분기 추가 | 4월 말에 5월 부부 회비를 미리 입금하는 정상 운영 케이스를 거래일 의무만으로 막으면 매번 일괄 확정에서 빠진다. 운영자가 두 명 매칭 + 부부 이력 등록이라는 두 신호를 모두 갖춘 record는 거래일 의무 검증을 우회 |
| D안에 `memberIds.length === 2` 가드 강제 | 1인 매칭에는 D안이 발동하지 않아야 이전 사고(이나래 가입 전 김가온 단독 입금) 재발 방지. 가드를 분기 진입 조건에 못박아 회귀 위험 차단 |
| `isKnownCouplePair`는 active/closed/future 모두 인정 | 운영자가 부부 관계를 시스템에 명시한 적이 있다는 신호 자체가 중요. 거래일이 어느 구간에 있든 두 명을 같이 매칭한 의도가 명확함 |
| 단가 판정을 별도 모듈로 추출 | 핸들러에 인라인으로 있으면 테스트가 어렵다. 동일 로직을 단건 confirm·upload에서도 재사용할 여지가 있어 분리 가치가 있다 |
| 단건 `confirm.ts`·`upload.ts`는 이번 변경에서 제외 | 단건은 사용자가 직접 월·금액을 지정하는 흐름이라 검증 정책이 다르고, upload는 매칭/검증 단계라 영향 범위가 다르다. 일괄 확정 사고를 먼저 막고 별도 PR에서 정합성 정리 예정 |

## 4. 검증

`coupleRateResolver.test.ts` 신규 — 11개 케이스 모두 통과:

- 부부 그룹·이력이 전혀 없으면 일반 단가
- 두 명 다 매칭되고 거래일에 모두 의무 → 풀매치 부부 단가 분배(`amountPerMemberPerMonth.sum === coupleAmount`)
- **부부 후보 2명이지만 한쪽이 거래일에 미가입 → 일반 단가** (이나래 5월 가입 전 김가온 단독 25,000원 입금 케이스)
- 부부 후보 2명이고 history active 구간이지만 한쪽 휴회 → 풀매치 X, member 1만 부부 단가
- group만 있고 history 없음, 거래일에 둘 다 의무 → 풀매치 부부 단가
- history `endedAt` 이후 거래일이고 group도 없음 → 일반 단가
- group fallback에서 배우자가 거래일 미가입 → 일반 단가
- group fallback에서 배우자가 거래일 의무 → 부부 단가 (단독 매칭이라 풀매치는 아님)
- **D안 — 4/29에 5월 부부 회비 사전 입금: 매칭 인원 2명 + 부부 이력 등록 → 풀매치 부부 단가**
- D안 — 부부 이력이 전혀 없으면 매칭 두 명이라도 D안 발동 X
- D안 가드 — 1명 매칭에는 D안 발동 X (이전 사고 재발 방지)
