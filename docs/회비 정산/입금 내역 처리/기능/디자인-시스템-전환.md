## 1. 배경 (Why)

회비 관리 기능은 디자인 시스템이 생기기 전에 만든 브랜치를 그대로 병합해 온 것이다. 그래서 옛 색·크기 클래스, 원시 입력 요소, `alert()`·`confirm()`, 직접 만든 모달이 남아 있었고 지킴이 테스트 33개가 실패했다.

- **지킴이 테스트가 실패한 채로는 CI가 통과하지 않는다.**
  - `confirm()`·`alert()` 35곳, 원시 `<input>`·`<select>` 28곳, 직접 만든 모달 5개 파일.
- **휴대폰에서 쓰기 어려웠다.**
  - 입금 내역 표가 가로로 넘쳤고, 행 안의 작은 아이콘 버튼으로 확정·건너뛰기를 해야 했다.

## 2. 도입한 개선

| 화면 | 바꾼 뒤 구성 |
| --- | --- |
| 입금 내역 처리 | `PageHeader` + 거래일 범위 + 상태 탭 + `Toolbar` + 필터 + `PaymentRecordsView`(표 + 상세 시트) + `BulkActionBar` |
| 입금 내역 업로드 | `PageHeader` + 업로드 영역 + 결과 숫자 + `PaymentRecordsView` |
| 회비 관리 대시보드 | `PageHeader` + `FeeDashboardView`(최근 업로드, 바로가기, 요약, 납부 현황 격자) |
| 회비 리포트 | `PageHeader` + 요약 + `DataTable` 2개 + 미납 회원 `ListGroup` |
| 업로드 이력 | `PageHeader` + `DataTable` |
| 회비 유형·부부·면제 | `PageHeader`(등록 버튼) + `DataTable` + 폼 `Sheet` |
| 회원 상세 | `PageHeader` + `MemberFeeDetailView`(`ListGroup` 3묶음 + 휴회 `Sheet`) |

## 3. 설계 의사결정

- **행 안 편집과 펼침 패널을 상세 시트 하나로 옮겼다.**
  - `DataTable`은 휴대폰에서 같은 행을 리스트로 그린다. 행에 동작 버튼을 두면 리스트에서는 쓸 수 없다.
  - → 그래서 행을 누르면 시트가 열리고, 회원 수정·월 선택·확정·건너뛰기·확정 취소·건너뜀 해제를 모두 그 안에서 한다.
  - 잃은 것: 한 건 건너뛰기가 1번 클릭에서 2번(행 → 버튼)으로 늘었다. 여러 건은 일괄 동작으로 처리한다.
- **일괄 동작은 PC 전용이 됐다.**
  - `DataTable`의 체크박스 열은 PC 표에만 있다. 휴대폰 리스트에는 행 선택이 없다.
  - 일괄 확정·건너뛰기는 수십 건을 훑으며 고르는 작업이라 PC에서 하는 것으로 본다.
- **MATCHED 탭의 일괄 확정은 연도·월을 시트에서 고른다.**
  - 옛 일괄 동작 막대에는 연도 선택과 12개월 버튼이 들어 있었다. 새 `BulkActionBar`는 버튼 몇 개만 놓는 줄이다.
  - → "선택 항목 확정"을 누르면 `BulkConfirmSheet`가 열린다. 결과를 받으면 닫히고, 거절하거나 오류가 나면 고른 월을 지킨 채 남는다.
- **정렬은 `DataTable`의 머리글 정렬을 쓴다.**
  - 페이지가 들고 있던 `sortBy`·`sortOrder` 상태와 `SortableTh`를 없앴다.
  - 기본 순서(거래일 내림차순)는 페이지가 `applySort`로 정해 넘기고, 머리글을 누르면 표가 그 위에서 다시 정렬한다.
  - 휴대폰 리스트는 기본 순서로만 보인다.
- **행별 선택 불가는 넣지 않았다.**
  - 옛 표는 매칭 회원이 없는 MATCHED 행의 체크박스를 숨겼다. `DataTable`에는 그 기능이 없다.
  - 그런 행을 골라 확정해도 서버가 그 건을 실패 사유로 돌려준다. 결과는 같다.
- **대시보드의 회원 × 12개월 격자는 `DataTable`로 바꾸지 않았다.**
  - 열이 15개라 리스트 전환이 의미가 없고, 이름 열 고정이 필요하다.
  - `PaymentDashboardTable`을 유지하고 토큰만 입혔다. 휴대폰에서는 가로로 민다.
- **회원 선택 드롭다운은 목록을 제자리에 그린다.**
  - 옛 `MemberMultiSelectDropdown`은 목록을 `body`로 옮겨 그렸다(표의 가로 스크롤에 잘리지 않으려고).
  - 시트 안에서는 대화상자 밖으로 나간 목록을 누르면 "바깥 누르기"로 처리되어 시트가 닫히고, 포커스 가두기 때문에 검색칸에 글자를 넣을 수 없다.
  - → 그래서 목록을 드롭다운 바로 아래에 그리도록 바꿨다.

## 4. 프런트 처리

### 부품 이름의 대응

| 옛 부품 | 새 부품 |
| --- | --- |
| `PaymentRecordTable` | `PaymentRecordsView` + `PaymentRecordSheet` |
| `organisms/membership-fee/BulkActionBar` | `organisms/table/BulkActionBar` + `BulkConfirmSheet` |
| `RecordStatusBadge` | `StatusChip domain="feeRecord"` |
| `PaymentStatusCell` | `PaymentDashboardTable` 안의 lucide 아이콘 |
| `CoupleHistoryManageList`, `ExemptionManageList` | `DataTable` |
| `CoupleHistoryUpsertModal` | `CoupleHistoryUpsertSheet` |
| `ExemptionRegisterModal` | `ExemptionRegisterSheet` |
| `fee-types.tsx` 안의 `FeeTypeFormModal` | `FeeTypeFormSheet` |
| `CoupleManageList`, `CoupleRegisterModal` | 삭제 (쓰는 곳이 없었다) |
| (없음) | `Notice`, `FeeDashboardView`, `MemberFeeDetailView`, `paymentRecordDisplay.ts` |

### 알림 방식의 대응

| 옛 방식 | 새 방식 |
| --- | --- |
| `confirm('…')` | `await confirm({ title, message, destructive })` (`useConfirm`) |
| `alert(오류)`, `alert('선택된 항목이 없습니다.')` | `toast.error(…)` |
| 일괄 결과 `alert` | 실패가 없으면 `toast.success`, 있으면 `confirm({ hideCancel: true })`로 사유 목록 표시 |
| 회원 상세의 화면 안 메시지 | `toast.success` / `toast.error` |

- **문구는 그대로다.** 담는 그릇만 바뀌었다.
- **일괄 결과의 사유 확인창은 기다리지 않는다.**
  - 선택 정리(성공한 건만 선택에서 빼기)가 확인창을 닫을 때까지 미뤄지면 안 된다.
- **`handleBulkConfirmSelected`는 `boolean`을 돌려준다.**
  - 결과를 받았으면 `true`. `BulkConfirmSheet`가 이 값으로 닫을지 정한다.

### 상세 시트의 상태

- **시트는 행 객체가 아니라 id를 들고 있다.**
  - 회원을 고치면 `records`가 새로 온다. 시트는 최신 `records`에서 그 건을 다시 찾아 그린다.
- **기본 선택은 열 때, 그리고 매칭 회원이 바뀔 때 잡는다.**
  - 차기 의무월 → 최종 납부월의 다음 달 → 추천 월 → 없음. 옛 "확정" 버튼을 누를 때와 같은 규칙이다.
  - 열 때마다 안쪽을 새로 만들어, 지난번에 고르던 월이 남지 않는다.
  - 시트 안에서 회원을 바꾸면 고르던 월을 버리고 새 회원의 기본값으로 다시 잡는다. 그대로 두면 앞 회원의 월로 새 회원을 확정하게 된다.
  - 같은 회원인 채 데이터만 새로 오면 고르던 월을 지킨다.
- **열어 둔 건이 목록에서 빠지면 열림 상태를 지운다.**
  - 대기 탭에서 회원을 붙이면 그 건은 매칭됨이 되어 목록에서 빠지고 시트가 닫힌다(옛 화면에서 행이 사라지던 것과 같다).
  - 지우지 않으면 매칭됨 탭으로 갔을 때 누르지 않았는데 시트가 열린다.

## 5. UX 디테일

- **색이 바뀐 곳**
  - 매칭됨: 파랑 → 초록(positive). 건너뜀: 노랑 → 회색(neutral). `statusTone.ts`의 `feeRecord` 정의를 따른다.
  - 초록 확정 버튼, 노랑 건너뛰기 버튼, 색색 바로가기 아이콘 → `Button`의 primary·secondary·destructive와 모노크롬 아이콘.
  - 색으로만 구분하던 글자(분홍 "부부", 파랑 "면제") → 회색 칩.
- **상태 탭**
  - 상태별 색 타일 6칸 → 건수가 붙은 칩 한 줄(`전체 12`). 고른 것만 강조색이다.
- **대시보드 격자의 칸**
  - `O`·`X`·`-` 글자와 휴회 이모지 → lucide 아이콘(`Check`·`X`·`Minus`·`Hospital`). 칸의 `title`은 그대로다.
  - 입금 시작월(왼쪽 굵은 선)과 탈퇴월(오른쪽 굵은 선) 표시는 유지한다.
- **설정 화면**
  - 행의 연필·휴지통 아이콘을 없앴다. 행을 누르면 수정 시트가 열리고, 삭제는 시트 아래에 있다.
  - 면제는 수정이 없어, 행을 누르면 삭제할지 바로 묻는다.
- **회원 상세**
  - 뒤로 가기 글자가 `← 회비 정산` 같은 온 곳의 이름에서 표준 "뒤로"가 됐다. 돌아가는 경로는 그대로다.
  - 휴회의 "수정"·"삭제" 글자 버튼 → 휴회 줄을 누르면 시트가 열린다.

## 6. 동작이 달라진 곳

의도해서 바꾼 것만 적는다. 그 밖의 동작과 요청은 전환 전과 같다.

| 구분 | 전 | 후 |
| --- | --- | --- |
| 한 건 건너뛰기 | 행의 버튼 1번 | 행 → 시트의 버튼 2번 |
| 일괄 선택 | 휴대폰에서도 가로 스크롤 표의 체크박스 | PC 표에서만 |
| 매칭 회원이 없는 MATCHED 행 | 체크박스 없음 | 체크 가능, 확정하면 서버가 실패 사유로 돌려줌 |
| 업로드 화면의 "회비 설정으로 이동" | 없는 화면(`/membership-fee/settings`) | `/membership-fee/settings/fee-types` |
| 리포트의 미납 회원 | 2·4열 칸 | 한 줄 목록 |
| 업로드 이력의 머리글 | "업로드일 / 파일명", "상태" | 업로드일·파일명·업로더·건수·거래일·상태 |
| 회원을 못 찾았을 때 | "목록으로" 링크 | `PageHeader`의 "뒤로" (같은 경로) |

## 7. 검증

- **자동 검사**
  - 지킴이 테스트: 33개 실패 → 전부 통과 (`npx jest src/__tests__/guards src/__tests__/styles`, 259개).
  - 전체 테스트: 1590개 통과 / 33개 실패 → 1718개 통과 / 실패 0.
  - `npx tsc --noEmit` 통과, 린트 오류 0.
- **새로 더한 테스트**
  - `useBulkPaymentActions`: 테스트 안에 복사해 둔 훅 대신 실제 훅을 검증한다(33개).
  - `PaymentRecordsView`·`BulkConfirmSheet` 30개, `FeeDashboardView` 14개, 설정 시트 3개 22개, `MemberFeeDetailView` 11개, `Notice` 2개, 업로드 이력·면제 화면 6개.
- **기능 보존 확인**
  - 전환 전 코드에서 뽑은 [기능 목록](../../디자인-시스템-전환-기능-목록.md) 122줄을 구현하지 않은 검토자가 전환 뒤 코드와 대조했다. 같음 74, 의도한 변경 48, 문제 0(처음에 나온 4건은 고쳤다). 결과는 그 문서의 "전환 뒤" 열에 있다.
- **화면 확인**
  - `/dev/admin-preview`에 `입금 내역 처리`, `회비 대시보드`, `회원 상세 (회비)`를 가짜 데이터로 올렸다.
