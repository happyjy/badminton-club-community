## 1. 배경 (Why)

[`입금내역-차기월-추천-휴회반영.md`](./입금내역-차기월-추천-휴회반영.md)에서 차기월(권장)이 휴회·탈퇴까지 반영해 정확히 계산되도록 개선했지만, **사용자는 결과 월(예: 5월)만 보고 그게 왜 그렇게 결정됐는지** 알 수 없었다.

예시: 마지막 납부가 2월인데 차기월(권장)이 5월로 표시될 때 — 3·4월이 휴회였는지, 의무 시작월이 미래라 그렇게 된 건지, 다른 이유가 있는지 화면에서 확인할 수 없다. 그래서 운영자가 "왜 5월이 추천됐지?" 라며 회원 상세를 다시 열어보는 일이 반복됐다.

## 2. 도입한 개선

### 2-1. `explainNextObligatedMonth` 함수 추가

`feeObligation.ts`에 차기월과 사유를 함께 반환하는 헬퍼를 신설:

```ts
explainNextObligatedMonth(
  lastPaid, feeObligationStartAt, leavePeriods, leftAt
): { next: { year: number; month: number } | null; reasons: string[] }
```

- 기존 `getNextObligatedMonth`와 동일한 24개월 탐색 루프를 사용하되, **건너뛴 휴회 월**을 누적해 `2026년 3~4월 휴회 제외`처럼 압축된 사유 라벨로 변환.
- `lastPaid`가 없고 `feeObligationStartAt`이 미래여서 차기월이 의무 시작월로 결정된 경우 `의무 시작월: 2026년 4월` 라벨 추가.
- `leftAt` 이후라 차기월이 null이면 `2026년 5월 탈퇴로 더 이상 의무 없음` 라벨을 reasons에 담아 반환.
- **단순 `lastPaid + 1`인 일반 케이스에선 reasons 빈 배열** — 호출부에서 사유 라인을 자동으로 숨길 수 있다.

### 2-2. records 응답에 `nextSuggestedReasons` 첨부

`attachLastPaidYearMonth`를 `getNextObligatedMonth` → `explainNextObligatedMonth`로 교체. 다중 매칭 시 가장 이른 차기 의무월을 채택하던 기존 정책을 유지하면서, **채택된 회원의 사유만** 응답에 싣는다(다른 회원 사유를 섞으면 사용자가 어느 회원 기준인지 혼동).

추가 DB 쿼리 0건 — 이미 회원 메타(`feeObligationStartAt`/`leftAt`/`leavePeriods`)를 한 번에 조회하던 자리에 함수만 교체.

### 2-3. PaymentRecord 타입 확장

```ts
interface PaymentRecord {
  // ...
  nextSuggestedReasons?: string[];
}
```

### 2-4. 프런트 — 확정 모달 표시

`PaymentRecordTable.tsx:560` 영역에 사유 라인을 추가:

```tsx
<p className="text-sm text-gray-600">
  최종 납부월: 2026년 2월 ·
  <span className="text-green-700 font-medium">
    차기월(권장): 2026년 5월
  </span>
</p>
{reasons.length > 0 && (
  <p className="text-xs text-gray-500 ml-4">
    └ {reasons.join(' · ')}
  </p>
)}
```

추가로 `nextSuggestedYearMonth`가 **명시적 null**(탈퇴 등)이면 기존 `+1개월` fallback을 끄고 `차기월(권장): 없음`으로 표시한다. 이전에는 fallback 때문에 탈퇴 후에도 다음 월이 추천되어 보일 수 있었다.

## 3. 의사결정

| 결정 | 이유 |
| --- | --- |
| 백엔드에서 사유 계산 | 입금 모달과 다른 화면(대시보드 등) 간 정책 비대칭 재발 방지. 1aee2a9 커밋이 직전에 정확히 그 비대칭을 잡은 직후 |
| 필요한 사유만 노출 (단순 +1은 빈 배열) | 일반 회원 row에서 사유 라인이 항상 떠 화면이 시끄러워지는 것을 막음 |
| 채택된 회원 사유만 (다중 매칭) | 부부 등 다중 매칭에서 두 회원 사유를 섞으면 어느 회원 기준인지 알 수 없음 |
| `nextSuggestedYearMonth === null` 분기 신설 | 탈퇴 후 `+1개월` fallback이 의미 없는 월을 추천하던 문제 해소 |

## 4. 검증

`feeObligation.test.ts`에 6개 케이스 추가:

- 단순 +1: reasons 빈 배열
- 휴회 끼어 차기월 밀림: `2026년 3~4월 휴회 제외`
- 비연속 휴회: 첫 의무월 도달 시 종료 — 이후 휴회는 reasons에 안 들어감
- 연도 경계 휴회: `2025년 12월~2026년 2월 휴회 제외`
- 의무 시작월이 미래: `의무 시작월: 2026년 4월`
- 탈퇴: `2026년 5월 탈퇴로 더 이상 의무 없음` (next null)
