## 1. 배경 (Why)

기존 입금 내역 처리 화면에는 두 가지 확정 경로가 있었다.

| 기존 경로               | 누구를 확정?        | 어느 월로?                                                                                |
| ----------------------- | ------------------- | ----------------------------------------------------------------------------------------- |
| 행 단위 [확정]          | 단일 record         | 사용자 선택 — 단, 기본값이 record별 "최종 납부월 + 1개월(차기월)"이라 매번 직접 바꿔야 함 |
| [매칭된 항목 일괄 확정] | 필터된 MATCHED 전체 | **자동(record별로 다름)** — 서버 `suggestMonths`가 결정                                   |

운영에서 자주 일어나는 패턴은 다음과 같다.

> 같은 월(예: "5월 회비")에 들어온 여러 입금 건을, 동일하게 5월로 확정하고 싶다.

그런데 위 두 경로 모두 이 패턴을 효율적으로 지원하지 못했다.

- 행 단위 [확정]: 사용자가 5월을 고르려면 매번 자동 채워진 차기월(예: 회원 A는 5월, B는 3월, C는 1월)을 손으로 다시 5월로 바꾸고 [추가] → [확정]을 N번 반복.
- [매칭된 항목 일괄 확정]: 서버가 record마다 자동 결정하므로 "전부 5월로"라는 사용자 의도를 표현할 수 없음.

→ 결과적으로 사용자는 일괄 버튼을 거의 사용하지 못하고 매번 같은 월을 손으로 클릭하고 있었다.

## 2. 도입한 개선

### 2-1. 체크박스 다중 선택 + 사용자 지정 월 일괄 확정

[매칭된 항목 일괄 확정] 버튼을 그대로 두고, 그 옆에 **사용자가 직접 record를 골라 동일 월로 확정**하는 새 흐름을 추가했다.

UI 흐름:

1. 표 헤더와 각 row(매칭됨 + 매칭 회원 있음)에 체크박스 표시
2. 한 건이라도 선택되면 표 위에 파란 툴바가 나타남
3. 툴바에서 연도·월 선택 → `[선택 항목 확정]` 클릭
4. 결과 alert에 `김철수: 이미 납부된 월이 포함됨 (2026년 5월)`처럼 입금자명 prefix 포함한 실패 사유 표시

선택 가능 조건: `record.status === 'MATCHED' && 매칭된 회원 ≥ 1명`. PENDING/CONFIRMED/SKIPPED/ERROR row에는 체크박스 자체가 렌더링되지 않고 빈 자리만 표시한다.

## 3. 기능 비교 정리

|                             | 누구를 확정?                 | 어느 월로?                            |
| --------------------------- | ---------------------------- | ------------------------------------- |
| 행 단위 [확정]              | 단일 record                  | 사용자 선택 (기본값: record별 차기월) |
| [매칭된 항목 일괄 확정]     | 필터된 MATCHED 전체          | 자동(record별 다름)                   |
| **(신규) [선택 항목 확정]** | **사용자가 체크한 record만** | **사용자 지정(전부 동일)**            |

세 방식이 겹치지 않는 페인을 각자 해결한다. "필터된 전체를 동일 월로(=옵션 3)" 케이스는 추후 필요 시 [매칭된 항목 일괄 확정] 버튼 옆에 "월 지정" 토글로 추가 가능 (현 구현은 보류).

## 4. 백엔드 처리

### 4-1. 스키마 확장

`bulkConfirmSchema`에 선택적 `selections` 필드 추가:

```ts
export const bulkConfirmSchema = z.object({
  recordIds: z.array(z.string()).min(1, ...),
  year: z.number().int().min(2020).max(2100),
  /**
   * 사용자가 지정한 연도·월. 있으면 record별 자동 추천(suggestMonths) 대신
   * 이 selections를 모든 record에 동일하게 적용한다.
   */
  selections: z.array(yearMonthSelectionSchema).optional(),
});
```

`BulkConfirmInput` 타입(`src/types/membership-fee.types.ts`)에도 동일하게 반영.

### 4-2. `bulk-confirm.ts` 핸들러 분기

요청 본문의 `selections` 유무로 record별 처리 흐름이 갈린다.

- **selections 없음**: 기존과 동일. `suggestMonths`로 record별 자동 결정 (회원별 의무월 / 휴회 / 거래일 / 기존 납부 월 고려).
- **selections 있음**: 자동 추천을 우회하고 사용자 지정 월을 모든 record에 동일 적용. 단, 다음 검증을 record별로 통과해야 하며 실패 시 record 단위로 fail 처리:
  - 지정 월 갯수 == `monthCount` (입금 금액 기준 월 수)
  - 모든 월이 의무월(`eligibleMonths`) 안 — 휴회·가입 이전이면 거부
  - 이미 납부된 월과 겹치지 않음

→ "전체가 동시에 실패"가 아니라 일부만 실패할 수 있고, 성공한 record id 목록(`results.success`)을 응답으로 반환한다.

### 4-3. 다중 안전망 (MATCHED 전용 보장)

선택·확정 동작이 MATCHED 상태에서만 가능하도록 3중으로 막혀 있다:

1. **프런트 — selectableRecordIds**: `PaymentRecordTable`이 헤더 "전체 선택" 대상으로 삼는 목록 자체가 `r.status === 'MATCHED' && getRecordMemberIds(r).length > 0` 필터.
2. **프런트 — row 체크박스 렌더링**: 각 row의 `isSelectable`이 같은 조건. 미충족이면 체크박스 대신 빈 공간 렌더.
3. **백엔드 — DB 조회 단계**: `bulk-confirm.ts`가 `prisma.paymentRecord.findMany`에서 `status: 'MATCHED'` + 매칭 회원 존재 조건으로 한 번 더 필터. 클라이언트가 우회해도 다른 상태 record는 처리 대상에서 빠진다.

## 6. UX 디테일

- 툴바는 `selectedRecordIds.length > 0`일 때만 표시 → 평소에는 화면이 깔끔.
- 툴바 안내 문구: "선택한 회원들에게 위에서 고른 연도·월을 동일하게 적용합니다. (의무월 외 / 이미 납부된 월은 자동으로 실패 처리됩니다)"
- 헤더 체크박스는 `indeterminate` 지원 (일부만 선택 시 시각적 구분).
- 실패 결과 alert 형식:

  ```
  3건 확정, 2건 실패

  실패 사유:
  • 김철수: 이미 납부된 월이 포함됨 (2026년 5월)
  • 이영희: 입금 부족 (30,000원) - 개별 확정에서 월 선택 후 부족 확정해주세요
  ```
