# 부부 회원 관리 — 화면 컨텍스트

> 위치: `src/pages/clubs/[id]/membership-fee/settings/couples.tsx`
> 라우트: `/clubs/[id]/membership-fee/settings/couples`

## 1. 목적

두 명의 회원을 부부로 묶어 **세대당 회비(coupleAmount)** 로 납부·확정 처리하기 위한 운영 화면. 부부 관계는 시점 단위로 누적되며, 진행 중인 관계가 곧 "현재 부부"로 인정된다. 등록·수정·삭제는 ADMIN 권한으로 수행.

## 2. 데이터 모델

| 모델 | 역할 | 보존 정책 |
| --- | --- | --- |
| **`CoupleHistory`** | 부부 관계의 시점 정본 (active=현재 부부, ended=과거) | **삭제하지 않고** `endedAt`만 채워 보존하는 것이 권장. 화면에서 잘못된 row는 삭제 가능 |
| `CoupleGroup` | 현재 부부 그룹 (1인 1그룹 unique) — `CoupleHistory.endedAt=null`인 row를 반영하는 캐시 성격 | history CRUD 시 서버 트랜잭션 안에서 자동 동기화 |
| `CoupleMember` | 그룹 멤버 매핑 | `CoupleGroup`에 종속 |

화면에서 다루는 것은 `CoupleHistory`이며, `CoupleGroup`은 다른 화면(대시보드 partner 표시 등)이 빠르게 "지금의 부부 회원" 을 조회하기 위한 캐시 역할을 유지한다.

## 3. API

### 부부 관계 이력 (정본 — 화면이 다루는 API)

화면이 호출하는 정본 엔드포인트. 시작·종료 시점은 연·월 단위로 입력받아 서버에서 `startedAt`=해당월 1일, `endedAt`=해당월 마지막 일 23:59:59로 변환해 저장한다. 모든 요청은 트랜잭션 안에서 `CoupleGroup`을 자동 동기화한다 (active 추가→그룹 생성, active 종료→그룹 삭제).

| 메소드 | 경로 | 동작 |
| --- | --- | --- |
| GET | `/api/clubs/[id]/membership-fee/couple-histories` | 이력 목록 조회 (멤버 이름 조인) |
| POST | `/api/clubs/[id]/membership-fee/couple-histories` | 신규 등록 + `CoupleGroup` ensure (active일 때) |
| PATCH | `/api/clubs/[id]/membership-fee/couple-histories/[historyId]` | 수정 + `CoupleGroup` 정리/생성 |
| DELETE | `/api/clubs/[id]/membership-fee/couple-histories/[historyId]` | 삭제 + active 짝이 더 이상 없으면 `CoupleGroup` 제거 |

active 충돌 검증: 한 회원에게 다른 partner와의 active row가 이미 있으면 409 의미의 400 응답 (서버에서 한국어 메시지로 안내).

### 부부 그룹 (캐시 — 다른 화면이 참조)

`CoupleGroup`을 직접 다루는 엔드포인트는 그대로 두지만, **부부 회원 관리 화면은 호출하지 않는다.** 다른 화면(대시보드 등)이 그룹 단위 조회를 위해 사용.

| 메소드 | 경로 | 동작 |
| --- | --- | --- |
| GET | `/api/clubs/[id]/membership-fee/couples` | 부부 그룹 목록 조회 |
| POST | `/api/clubs/[id]/membership-fee/couples` | 부부 그룹 생성 + `CoupleHistory` row 추가 |
| DELETE | `/api/clubs/[id]/membership-fee/couples/[groupId]` | 부부 그룹 삭제 + `CoupleHistory.endedAt` 종료 |

자세한 통합 의도는 [부부 이력 도입](./기능/부부-이력-도입.md)의 "수동 보정 화면" 섹션 참고.

## 4. 등록·해체 시 데이터 흐름

### 등록 (POST)

```
1. memberIds가 다른 active 그룹에 속해있지 않은지 확인
2. 트랜잭션:
   - CoupleHistory.updateMany: 혹시 남아있는 active row(endedAt=null)를 안전상 종료 (정상 흐름이라면 0건)
   - CoupleGroup 생성 + CoupleMember create
   - CoupleHistory createMany: 멤버 쌍의 양방향 row 추가 (A→B, B→A)
     · startedAt = CoupleGroup.createdAt
     · endedAt   = null
```

### 해체 (DELETE)

```
1. CoupleGroup 조회 (members 포함)
2. 트랜잭션:
   - CoupleHistory.updateMany: 해당 멤버의 endedAt=null row를 endedAt=now()로 종료
   - CoupleGroup 삭제 (cascade로 CoupleMember 함께 삭제)
```

## 5. 입금 처리에 미치는 영향

거래일 기준 부부 단가 판정은 `src/lib/membership-fee/coupleHistory.ts`의 `wasCoupleAt`을 사용한다. 다음 위치에서 사용:

- `bulk-confirm.ts` — 일괄 확정 시 부부 단가 판정 (이력 우선, 그룹 fallback)
- `records/[recordId]/confirm.ts` — 단건 확정 시 부부 단가 판정 (이력 우선, 그룹 fallback)

자세한 내용은 [기능 문서: 부부 이력 도입](./기능/부부-이력-도입.md) 참고.

## 6. 백필

기존 `CoupleGroup`은 `src/scripts/backfillCoupleHistory.ts`로 1회 백필.

```bash
npx ts-node src/scripts/backfillCoupleHistory.ts
```

- 각 그룹 → (A→B, B→A) 양방향 row 생성
- `startedAt = CoupleGroup.createdAt`, `endedAt = null`
- 같은 (clubMemberId, startedAt, partnerClubMemberId) 조합이 이미 있으면 스킵
- 멤버가 2명이 아닌 비정상 그룹은 경고 출력 후 스킵

## 6-1. 화면 구성

- **`PageHeader`(등록 버튼) + `DataTable` + `CoupleHistoryUpsertSheet`.**
  - 표의 열: 회원 → 배우자 / 기간 / 상태(진행 중이면 `active`).
  - 행을 누르면 수정 시트가 열린다. 삭제는 시트 아래에 있고 `useConfirm`으로 한 번 더 묻는다.
  - 휴대폰에서는 같은 행이 리스트로 보인다.
- 결정의 배경은 [디자인 시스템 전환](../입금%20내역%20처리/기능/디자인-시스템-전환.md).
