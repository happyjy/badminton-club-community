# 탈퇴 회원 납부 현황 표시 기획

## 1. 배경 (Why)

현재 회비 대시보드의 "회원별 납부 현황" 테이블은 `status: 'APPROVED'`인 회원만 조회한다.
따라서 **중도 탈퇴한 회원**은 테이블에서 완전히 사라지며, 해당 연도에 납부했던 이력도 확인할 수 없다.

문제:

- 2026년에 활동하다가 탈퇴한 회원의 납부 이력을 2026년 대시보드에서 볼 수 없음
- 탈퇴 전 미납이 있었는지 확인 불가
- 연간 정산 시 "누가 언제까지 있었는지" 파악 어려움

→ 탈퇴 회원도 **해당 연도 납부 현황에 계속 표시**하되, 탈퇴 상태와 시점을 시각적으로 구분해야 한다.

---

## 2. 목표

1. 탈퇴(`LEFT`) 회원이 해당 연도 납부 현황 테이블에 계속 노출된다.
2. 탈퇴 시점(월)을 시각적으로 표시하여, 언제까지 의무가 있었는지 한눈에 파악할 수 있다.
3. 탈퇴 이후 월은 납부 의무에서 자동 제외된다.w
4. 기존 "입금 시작" 표시와 대칭적인 UX를 유지한다.

## 5. DB 스키마 변경

### 5.1 ClubMember에 `leftAt` 필드 추가

```prisma
// prisma/schema/club.prisma
model ClubMember {
  // ... 기존 필드
  feeObligationStartAt     DateTime?

  /// 탈퇴일. status가 'LEFT'로 변경될 때 자동 설정.
  /// 해당 년·월까지 회비 의무 있음. null이면 탈퇴하지 않은 회원.
  /// 관리자가 회원 상세 페이지에서 수동 수정 가능.
  leftAt                   DateTime?

  // Relations ...
}
```

### 5.2 마이그레이션

```sql
ALTER TABLE "ClubMember" ADD COLUMN "leftAt" TIMESTAMP;
```

### 5.3 기존 탈퇴 회원 데이터 보정

- 이미 `status = 'LEFT'`인 회원 중 `leftAt`이 null인 경우 → `updatedAt` 값으로 보정하거나, 관리자가 수동 설정할 수 있도록 안내

### 5.4 상태 변경 API에서 `leftAt` 자동 설정

현재 회원 상태 변경 API (`src/pages/api/clubs/[id]/members/[userId]/status.ts`)는 `status`만 업데이트하고 `leftAt`을 설정하지 않는다. 다음 로직을 추가:

```
- status → 'LEFT'로 변경 시: leftAt = 현재 시점 (new Date())
- status → 'LEFT' 이외로 변경 시 (예: LEFT → APPROVED 복귀): leftAt = null 로 초기화
```

> **주의: LEFT → APPROVED → LEFT 재탈퇴 시나리오**
> 관리자가 탈퇴 회원을 다시 APPROVED로 복귀시킨 후, 다시 LEFT로 변경하면
> `leftAt`이 재탈퇴 시점으로 자동 업데이트된다. 이전 탈퇴 이력은 유지되지 않으므로,
> 필요 시 관리자가 회원 상세 페이지에서 탈퇴일을 수동으로 조정할 수 있다.

## 6. 의무 월 계산 변경

### 6.1 `feeObligation.ts` 수정

`getObligationMonths`에 `leftAt` 파라미터 추가:

```
기존: 시작월 ~ 12월 (휴회 제외)
변경: 시작월 ~ min(탈퇴월, 12월) (휴회 제외)
```

**예시:**

```
회원 A: 2026년 1월 가입, 2026년 8월 탈퇴
→ 의무 월: [1, 2, 3, 4, 5, 6, 7, 8]
→ 9~12월: 의무 없음 ("-" 표시)
→ 8월 셀: 빨간색 오른쪽 테두리

회원 B: 2026년 4월 가입, 2026년 10월 탈퇴, 6~7월 휴회
→ 의무 월: [4, 5, 8, 9, 10]
→ 1~3월: 가입 전 ("-"), 6~7월: 휴회 ("🏥"), 11~12월: 탈퇴 후 ("-")
→ 4월 셀: 파란색 왼쪽 테두리 (입금 시작)
→ 10월 셀: 빨간색 오른쪽 테두리 (탈퇴)
```

## 7. API 변경

### 7.1 Dashboard API (`dashboard.ts`)

**쿼리 변경:**

```typescript
// 기존
where: { clubId, status: 'APPROVED' }

// 변경
where: {
  clubId,
  OR: [
    { status: 'APPROVED' },
    {
      status: 'LEFT',
      leftAt: { gte: new Date(year, 0, 1) },        // 해당 연도 이후 탈퇴
      feeObligationStartAt: { lt: new Date(year + 1, 0, 1) }, // 해당 연도 이전 가입
    },
    {
      status: 'LEFT',
      leftAt: null,                                    // leftAt 미설정 (기존 데이터)
      feeObligationStartAt: { lt: new Date(year + 1, 0, 1) },
    },
  ],
}
```

**응답에 추가할 필드:**

```typescript
// select에 추가
select: {
  // ... 기존 필드
  status: true,
  leftAt: true,
}
```

### 7.2 MemberPaymentStatus 타입 확장

```typescript
export interface MemberPaymentStatus {
  // ... 기존 필드
```

## 9. 회원 상세 페이지 — 탈퇴 관련 필드 추가

### 9.1 배경

회비 대시보드 테이블에서 회원 이름을 클릭하면 회원 상세 페이지로 진입한다.

```typescriptreact
// src/components/organisms/membership-fee/PaymentDashboardTable.tsx:103
<Link
  href={`/clubs/${clubId}/members/${member.userId}?from=/clubs/${clubId}/membership-fee&fromLabel=회비 정산`}
  className="hover:underline text-blue-600"
  title="회원 정보에서 입금 시작일 수정"
>
```

현재 회원 상세 페이지에는 **가입일**, **회비 입금 시작월** 필드가 있다.
탈퇴 회원의 경우 이에 대응하는 **탈퇴일**, **회비 마지막 월** 필드가 필요하다.

### 9.2 추가 필드

| 필드               | 표시 조건           | 타입                  | 설명                                                                           |
| ------------------ | ------------------- | --------------------- | ------------------------------------------------------------------------------ |
| **탈퇴일**         | `status === 'LEFT'` | 수정 가능 (날짜 선택) | `leftAt` 값을 `YYYY.MM.DD` 형식으로 표시. 관리자가 수정 가능                   |
| **회비 마지막 월** | `status === 'LEFT'` | 수정 가능 (셀렉트)    | "회비 입금 시작월"과 동일한 UI. 관리자가 탈퇴 회원의 마지막 의무월을 조정 가능 |

### 9.3 UI 배치

기존 "가입일 / 회비 입금 시작월" 영역 아래에 탈퇴 관련 필드를 배치:

```
가입일:            2026.01.15
회비 입금 시작월:  [2026년] [1월 ▾]     ← 기존 (수정 가능)

탈퇴일:            [2026.08.20 ▾]       ← 신규 (수정 가능)
회비 마지막 월:    [2026년] [8월 ▾]     ← 신규 (수정 가능)
```

- 탈퇴 회원이 아닌 경우 (`status !== 'LEFT'`) 이 두 필드는 표시하지 않음
- "회비 마지막 월" 변경 시 해당 연도의 의무 월 계산에 즉시 반영

### 9.4 탈퇴일 수정이 필요한 이유

관리자가 회원 관리 페이지에서 상태를 자유롭게 변경할 수 있다:

- `LEFT` → `APPROVED` (복귀) → 다시 `LEFT` (재탈퇴)
- 이 경우 `leftAt`이 재탈퇴 시점으로 자동 업데이트됨
- 실제 탈퇴일과 시스템에 기록된 날짜가 다를 수 있으므로, 관리자가 직접 보정할 수 있어야 함

### 9.5 DB 필드

`ClubMember` 테이블(`prisma/schema/club.prisma`)의 `leftAt` 컬럼을 사용:

| 테이블       | 컬럼     | 타입        | 설명                                 |
| ------------ | -------- | ----------- | ------------------------------------ |
| `ClubMember` | `leftAt` | `DateTime?` | 탈퇴일. 5.1절에서 추가하는 신규 컬럼 |

- 탈퇴 처리 시 `leftAt`에 현재 시점 자동 저장 (상태 변경 API, 5.4절 참고)
- 관리자가 회원 상세 페이지에서 `leftAt` 직접 수정 가능
- 회비 마지막 월 기본값: `leftAt`의 년·월 (관리자가 별도로 조정 가능)

> `feeObligationStartAt`이 회비 시작월을 관리하듯, `leftAt`의 년·월이 회비 종료월의 기본값이 된다. 두 값 모두 관리자가 회원 상세 페이지에서 수정 가능하다.

### 9.6 API

- 회원 상세 조회 API: `leftAt` 필드 포함하여 응답
- 회원 상세 수정 API: 탈퇴일(`leftAt`) 수정 + 회비 마지막 월 수정 지원

## 10. 부부 회원 중 한 명 탈퇴 시

| 상황         | 처리                                                                                                                             |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| 한 명만 탈퇴 | 부부 행 유지, 탈퇴한 회원 이름에 취소선 + 탈퇴 뱃지. 탈퇴월 이후는 남은 회원만 "일반" 요금으로 전환 (별도 관리자 조치 필요 안내) |
| 둘 다 탈퇴   | 부부 행 전체에 탈퇴 표시. 늦은 탈퇴월 기준으로 의무 종료                                                                         |

> 부부 중 한 명 탈퇴 시 요금 체계 전환은 복잡하므로 Phase 1에서는 **표시만** 하고, 요금 전환은 관리자가 수동으로 회비 유형을 변경하도록 안내한다.

## 10. 구현 순서

### Phase 1: DB + API + 기본 표시

1. `ClubMember`에 `leftAt` 필드 추가 + 마이그레이션
2. 기존 `LEFT` 회원 `leftAt` 데이터 보정 (updatedAt 기반)
3. `feeObligation.ts`에 탈퇴월 종료 로직 추가
4. `dashboard.ts` API에서 `LEFT` 회원 포함 조회 + 응답 필드 추가
5. `MemberPaymentStatus` 타입 확장
6. `PaymentDashboardTable.tsx`에 탈퇴 뱃지 + 탈퇴월 테두리 + 탈퇴 후 셀 표시
7. 탈퇴 회원 정렬 (아래쪽 별도 그룹)
8. 회원 상세 페이지에 "탈퇴일" (읽기 전용) + "회비 마지막 월" (수정 가능) 필드 추가

### Phase 2: 세부 기능

9. 요약 카드에 탈퇴 회원 수 반영
10. 미납/납부완료 필터에서 탈퇴 회원 올바르게 동작
11. 부부 중 한 명 탈퇴 시 표시 처리
