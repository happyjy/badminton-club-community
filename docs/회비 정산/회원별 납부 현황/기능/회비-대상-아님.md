# 회비 대상 아님 (코치 등)

작성일: 2026-11-23
관련 화면: `/clubs/[id]/members/[userId]` (회원 상세), `/clubs/[id]/membership-fee` (대시보드), 납부현황 내보내기, 리포트의 미납 회원 목록
설계 문서: [`2026-11-23-manual-payment-and-fee-excluded-design.md`](../../../superpowers/specs/2026-11-23-manual-payment-and-fee-excluded-design.md)

## 1. 배경 (Why)

- **재무의 표는 코치를 아예 싣지 않는다.**
  - 명예회원은 파란 면제 줄로 싣지만, 코치는 회비 대상이 아닌 사람이다.
- **앱에는 이것을 나타낼 방법이 없었다.**
  - 회비 시작월을 비우면 1월부터 의무로 본다(`feeObligation.ts`, 하위 호환).
  - 코치 C(2026-08 가입)는 8월부터 미납으로, 코치 D는 면제(사유 "코치님") 줄로 나와 재무 표와 달랐다.

## 2. 도입한 개선

- **회원 상세의 회비 설정에 "회비 대상 아님 (코치 등)" 체크를 둔다.**
  - 체크하는 즉시 저장한다. 회비 설정의 [저장] 버튼(시작월·탈퇴일)과는 따로다. 그래서 버튼 아래에 둔다.
- **켠 회원은 회비 화면에서 빠진다.**

| 곳 | 빠지는 것 |
| --- | --- |
| 대시보드 | 회원별 납부 현황, 월별 납부율, 전체 회원 수, 면제 회원 수 |
| 납부현황 내보내기 | 엑셀의 줄 |
| 리포트 | 미납 회원 목록 |

- **그 회원의 통장 입금은 총 수입에 남는다.**
  - 실제로 회비 통장에 들어온 돈이기 때문이다.

## 3. 설계 의사결정

| 결정 | 이유 | 버린 대안 |
| --- | --- | --- |
| `ClubMember`에 칸 하나(`feeExcluded`) | 모든 해에 걸린다(직책과 같다). 지금 대상은 처음부터 코치다 | 기간 단위 — 지금 필요한 경우가 없다 |
| | | 면제 사유 "코치" — 재무 표에 없는 면제 줄이 생긴다 |
| 대시보드와 내보내기가 함께 쓰는 로더의 회원 조회에서 거른다 | 한 곳을 고치면 둘 다 빠진다 | 화면마다 거름 |
| 면제 회원 수를 조회된 회원 안에서 센다 | 전에는 클럽 전체 면제를 셌다. 회비 대상 아님 회원의 면제가 수에 남지 않게 | 그대로 둠 |
| 입금 매칭 후보·부부 관리·면제 등록 화면은 그대로 둔다 | 코치가 회비 통장에 돈을 보내는 일은 드물고, 보내면 다른 회원처럼 처리할 수 있어야 한다 | 모든 화면에서 숨김 |

- **대가**: 켠 회원은 지난해 표에서도 빠진다.

## 4. 백엔드 처리

- **스키마**: `ClubMember.feeExcluded Boolean @default(false)`. 기존 회원은 모두 `false`다.
- **`PATCH …/members/[userId]/fee-obligation`**: `feeExcluded`를 보내면 그 칸만 고친다(보낸 항목만 고치는 기존 방식). 불리언이 아니면 400 "회비 대상 여부를 확인해주세요".
- **`loadMemberYearData`**: 회원 조회 조건에 `feeExcluded: false`. `exemptMemberCount`는 조회된 회원 가운데 면제가 있는 회원 수.
- **`unpaid.ts`**: 회원 조회 조건에 `feeExcluded: false`.

## 5. 프런트 처리와 UX 디테일

- 체크를 바꾸면 "회비 대상 아님으로 바꿨습니다." / "회비 대상으로 바꿨습니다." 토스트를 보이고 대시보드 캐시를 비운다.
- 저장 중에는 체크를 바꿀 수 없다.
