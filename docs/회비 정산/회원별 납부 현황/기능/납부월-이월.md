# 납부월 이월 (의무가 없어진 달의 납부)

작성일: 2026-10-10
관련 화면: `/clubs/[id]/members/[userId]` (회원 상세), `/clubs/[id]/membership-fee` (대시보드 격자)
설계 문서: [`2026-10-10-membership-fee-pipeline-and-export-design.md`](../../../superpowers/specs/2026-10-10-membership-fee-pipeline-and-export-design.md) §5.8

- `src/pages/api/clubs/[id]/membership-fee/payments/shift.ts` — `POST { paymentIds }`

## 1. 배경 (Why)

- **회비를 낸 뒤에 그 달의 의무가 없어지는 일이 있다.**
  - 4월 회비를 내고 나서 4월 병가를 등록한다("4월병가, 5월로 이월").
  - 연납을 낸 뒤 중간에 휴회한다.
- **그 납부는 주인 없는 달에 걸려 있다.**
  - 표에서는 휴회 칸으로 보이고, 다음 의무월은 미납으로 보인다.
  - 재무는 확정을 취소하고 달을 다시 골라 확정해야 했다.

## 2. 도입한 개선

- **의무가 없는 달의 납부를 그 회원의 다음 미납 의무월로 옮긴다.**
  - 납부의 연·월만 바뀐다. 어느 입금에서 나온 납부인지와 금액은 그대로다.
- **휴회를 저장하면 바로 묻는다.**
  - "휴회 기간에 납부 N건이 있습니다 … 다음 의무월로 이월할까요?"
- **나중에도 옮길 수 있다.**
  - 회원 상세의 휴회 묶음 위에 "의무가 없는 달에 낸 회비 N건이 있습니다" 안내와 [다음 의무월로 이월] 버튼이 남는다.
- **대시보드 격자에서도 드러난다.**
  - 그 칸의 설명이 "휴회/병가 · 납부 있음 — 이월 필요"가 되고 아이콘이 주의 색으로 바뀐다.

## 3. 설계 의사결정

| 결정 | 이유 | 버린 대안 |
| --- | --- | --- |
| 옮길 달은 서버가 정한다 (다음 미납 의무월) | 화면이 달을 고르게 하면 이미 낸 달·휴회 달을 다시 검증해야 한다 | 재무가 달을 고름 |
| 의무가 있는 달의 납부는 옮기지 않는다 | 화면이 잘못된 id를 보내도 멀쩡한 납부가 옮겨지지 않는다 | 고른 것은 무엇이든 옮김 |
| 같은 회원의 여러 건은 앞 달부터 차례로 다른 달을 받는다 | 두 달을 쉬면 두 건이 같은 달로 몰린다 | 건마다 따로 계산 |
| 휴회뿐 아니라 가입 전·탈퇴 후의 납부도 같은 자리에서 보인다 | 원인이 달라도 할 일이 같다. 탈퇴 후의 납부는 옮길 달이 없어 실패로 알려 준다(환불할 돈) | 휴회만 다룸 |
| 그 목록은 휴회 목록 API에 싣는다 | 회원 상세 API는 본인도 부르는 일반 API라 회비 정보를 섞지 않는다 | 회원 상세 API |
| 24개월 안에서만 찾는다 | 끝을 정하지 않은 휴회에서 끝없이 돌지 않는다 | 제한 없음 |

## 4. 백엔드 처리

- **`POST /api/clubs/[id]/membership-fee/payments/shift`** `{ paymentIds }` (관리자)
  - `planPaymentShifts`가 건마다 옮길 달을 정한다.
  - 저장은 원래 연·월 조건을 다시 건 `updateMany`를 한 트랜잭션으로 한다.
  - 응답은 [일괄 처리 형식](../../../../.claude/rules/bulk-action-pattern.md)이고, `failed[].recordId`에는 납부 내역의 id가 들어간다.

| 실패 사유 | 경우 |
| --- | --- |
| 납부 내역을 찾을 수 없습니다 | 없는 id, 다른 클럽의 납부 |
| 의무가 있는 달의 납부는 옮길 수 없습니다 | 옮길 대상이 아님 |
| 옮길 의무월이 없습니다 | 탈퇴해 더는 의무가 없음 |
| 그사이 바뀐 납부 내역입니다 | 요청 사이에 다른 달로 옮겨졌거나 지워짐 |

- **휴회 저장 (`POST`·`PATCH`)** 응답에 `paymentsInRange: { id, year, month, amount }[]`.
- **휴회 목록 (`GET`)** 응답에 `orphanPayments`(의무가 없는 달에 걸린 납부 전부).
- **대시보드** 응답의 회원마다 `orphanPaidMonths`.

## 5. 프런트 처리와 UX 디테일

- **휴회 저장 직후의 창은 시트가 닫히는 것을 기다리게 하지 않는다.**
- **결과는 다른 일괄 동작과 같은 꼴로 알린다.**
  - 모두 성공하면 "N건 이월, 0건 실패" 토스트.
  - 실패가 있으면 "2026년 4월: 옮길 의무월이 없습니다"처럼 달과 사유를 확인창으로 보인다.
- **옮긴 뒤에는 안내가 사라지고 대시보드를 새로 읽는다.**
