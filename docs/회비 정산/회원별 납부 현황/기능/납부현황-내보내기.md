## 1. 배경 (Why)

- **재무의 최종 결과물은 "YYYY년 월회비 납부현황" 표 한 장이다.**
  - 재무가 통장을 보며 손으로 색을 칠해 만들어 왔다.
  - 대시보드가 같은 정보를 이미 계산하지만 표로 꺼낼 방법이 없었다.
- **표에는 대시보드에 없는 것이 두 가지 있다.**
  - 임원을 위쪽에 정해진 순서로 놓고 비고에 직책을 적는다.
  - 병가는 사유를 칸에 적는다.

## 2. 도입한 개선

- **대시보드의 [납부현황 내보내기] 버튼이 보고 있는 해의 표를 엑셀로 내려 준다.**
  - 파일 이름: `회비납부현황_YYYY_YYYYMMDD.xlsx` (뒤의 날짜는 내보낸 날, 한국 시각).
- **표 모양은 재무의 기존 표와 같다.**

| 항목 | 내용 |
| --- | --- |
| 제목 | "YYYY년 월회비 납부현황", 오른쪽 위에 "반영일 : YYYY.M.D" |
| 범례 | 완납 · 미납 · 면제 · 병가 · 해당없음 |
| 열 | NO · 성명 · 1월 ~ 12월 · 비고 |
| 행 순서 | 직책이 있는 회원을 정렬 순서대로 먼저, 그 아래 굵은 선, 나머지는 가나다순 |
| 비고 | 직책, 탈퇴 회원은 "YYYY.MM 탈퇴" |
| 인쇄 | 쪽마다 범례와 머리글 반복, 쪽 번호 |

### 2-1. 칸의 상태

| 상태 | 조건 | 표시 |
| --- | --- | --- |
| 완납 | 그 달 납부가 있음 (면제 회원이어도) | 노란 칸 |
| 미납 | 의무월인데 납부가 없고, 이번 달이거나 지난 달 | 빨간 칸 |
| 면제 | 그 해 면제 회원이고 납부가 없음. 이번 달까지만 칠한다 | 파란 칸 |
| 병가 | 휴회 기간. 아직 오지 않은 달도 칠한다 | 초록 칸. 이어진 병가의 첫 달에 사유를 적는다 |
| 해당없음 | 가입 전 · 탈퇴 후 | 회색 칸 |
| (빈칸) | 아직 오지 않은 달 | 칠하지 않음 |

### 2-2. 직책

- **회원 상세에 "직책"과 "정렬 순서"를 둔다.**
  - `ClubMember.position`(회장·총무 등), `ClubMember.positionOrder`(작을수록 위).
  - 직책을 지우면 정렬 순서도 함께 지운다.

## 3. 설계 의사결정

| 결정 | 이유 | 버린 대안 |
| --- | --- | --- |
| 대시보드와 내보내기가 같은 조회·계산을 쓴다 | 화면과 파일이 다를 수 없다 | 내보내기용 계산을 따로 둠 |
| 면제 회원도 낸 달은 완납으로 둔다 | 재무의 표에서 연중에 임원이 된 회원은 "1~3월 완납 + 4월부터 면제", 연회비를 낸 회장은 전부 완납이다 | 면제면 납부를 무시 — DB의 면제를 지워야 표가 맞는다 |
| 탈퇴 회원은 빼지 않고 활동 회원 아래에 따로 모은다 | 빼면 그 해에 낸 회비가 표에서 사라진다. 위쪽 목록은 재무의 표와 같은 구성으로 남는다 | 탈퇴 회원 제외 |
| 그 해에 의무월도 휴회월도 없는 회원은 싣지 않는다 | 다음 해부터 의무인 회원, 전년에 탈퇴한 회원이 회색 줄로 표를 채운다 | 전체 회원 |
| 회원 정보 저장 API는 보낸 항목만 고친다 | 직책만 저장할 때 시작월이 지워지지 않아야 한다 | 모든 항목을 매번 보냄 |
| 엑셀은 `exceljs`로 만든다 | 칸 색·테두리·인쇄 설정이 필요하다 (`xlsx`는 읽기에만 쓴다) | CSV |

## 4. 백엔드 처리

- **`loadMemberYearData(prisma, clubId, year)`** 가 회원·휴회·부부·면제·납부를 한 번에 읽는다.
- **`buildMemberYearStatus(year, member, today)`** 가 회원 한 명의 의무월·휴회월·칸 상태·휴회 사유를 낸다.
  - 대시보드가 쓰던 필드(`type`, `payments`, `obligationMonths` 등)는 그대로 낸다.
  - 내보내기용으로 `cells`, `leaveReasons`, `position`, `positionOrder`를 더했다.
  - 의무가 없는데 납부가 걸린 달(`orphanPaidMonths`)도 여기서 낸다 → [납부월 이월](./납부월-이월.md).
- **`GET /api/clubs/[id]/membership-fee/export?year=`** (관리자)
  - 성공하면 파일 본문을, 실패하면 다른 API와 같은 `{ error, status }`를 보낸다.

## 5. 프런트 처리와 UX 디테일

- **버튼은 대시보드의 연도 줄 오른쪽에 있다.**
  - 누르면 "내보내는 중…"으로 바뀌고 다시 누를 수 없다.
  - 끝나면 "<파일 이름> 저장" 토스트.
- **실패하면 서버가 알려 준 사유를 보인다.**
  - 파일(blob)로 요청하면 실패 응답의 JSON도 Blob으로 오므로 읽어서 `error`를 꺼낸다.
  - 읽을 수 없으면 "내보내기에 실패했습니다."

### 6-1. 재무의 기존 표와의 대조 (2026-10-11)

재무가 손으로 만든 2026년 표(4월 20일 기준, 89명 × 1~4월)와 내보내기의 칸 상태를 견줬다.

| 항목 | 결과 |
| --- | --- |
| 대조한 회원 | 89 / 89명 |
| 칸 일치 | 321 / 356 = 90.2% |
| 어긋난 회원 | 22명 (35칸) |

| 재무 표 → 내보내기 | 칸 | 회원 | 그 달의 납부 | 까닭 |
| --- | --- | --- | --- | --- |
| 완납 → 해당없음 | 16 | 11명 | DB에 없음 | 의무 시작월이 실제보다 늦게 들어가 있다. 그 달 입금은 뒤의 달로 확정돼 있다 |
| 미납 → 완납 | 4 | 4명 | 있음 | 표를 만든 뒤에 입금이 등록됐다. 정상 |
| 완납 → 병가 | 4 | 3명 | 없음 | DB의 휴회 기간이 표와 다르다 |
| 병가 → 미납 | 4 | 1명 | 없음 | 휴회가 DB에 등록돼 있지 않다 |
| 완납 → 미납 | 3 | 3명 | 없음 | 그 달 입금이 확정돼 있지 않다 |
| 면제 → 완납 | 3 | 1명 | 있음 | 면제 회원에게 납부가 확정돼 있다. 대납이 본인 납부로 잡혔는지 확인이 필요하다 |
| 해당없음 → 병가 | 1 | 1명 | 없음 | 의무 시작월·휴회 기간 차이 |

- **계산이 틀려서 어긋난 칸은 없다.**
  - 35칸 모두 DB에 들어 있는 값(의무 시작월·휴회·납부)이 재무의 표와 다른 경우다.
- **회원별 결과와 원본 자료는 저장소에 두지 않는다.**
  - 실명과 납부 상태가 들어 있어 로컬 `docs/회비 정산/data/`에만 둔다(`.gitignore`).
  - 다시 돌리려면 그 폴더에 이미지 데이터를 두고 `src/scripts/compareExportWithImage.ts`를 실행한다(`--detail`은 회원별 출력).
