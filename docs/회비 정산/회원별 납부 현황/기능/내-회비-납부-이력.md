## 1. 배경 (Why)

- **재무님은 회비 관리 화면에서 모든 회원의 납부를 보지만, 회원은 자기 납부를 볼 곳이 없었다.**
  - 회원은 몇 월분을 냈는지, 그걸 언제 입금했는지 알려면 재무님께 물어야 했다.
  - 재무님도 회원 상세에서는 휴회·시작월 같은 설정만 보여, 달마다 얼마를 언제 냈는지는 대시보드 표와 입금 내역을 오가며 맞춰 봐야 했다.
- **목표: 같은 "납부 이력"을 회원 본인과 임원이 함께 본다.**
  - 언제 빠졌는지(휴회), 언제 들어왔는지(입금 시작), 금액이 언제 달라졌는지(부부·단가)가 달별 목록에서 드러나야 한다.

## 2. 도입한 개선

- **회원 메뉴에 "내 회비"가 생겼다.**
  - 회비를 앱으로 관리하는 클럽(활성 회비 유형이 있음)의 회원에게만 보인다. 휴대폰은 "더보기" 안, PC는 사이드바.
- **회원 상세의 "휴회/병가 기간" 위에 "납부 이력"이 생겼다.** 내 회비와 같은 부품이다.
- **한 화면에 보이는 것**

| 묶음 | 내용 |
| --- | --- |
| 반영 시각 | "통장 거래 11월 20일 오후 2:30까지 반영". 올해가 아니면 연도를 붙인다. 내역이 없으면 "아직 올라온 통장 내역이 없어요" |
| 요약 | "2026년 미납 2달 · 50,000원", "월 회비 1~4월 25,000원 · 5월부터 22,500원 (부부)" |
| 확인 중인 입금 | 통장 엑셀로 올라왔고 이 회원에게 매칭됐지만 아직 확정하지 않은 회비 입금. 줄 끝에 "재무님 확인 중" |
| 납부 이력 | 달마다 상태 칩(낸 달·미납·휴회·면제)과 "25,000원 · 5월 1일 입금 · 입금자 OOO · 부부" |
| 휴회 | 고른 해와 겹치는 휴회 기간 (내 회비에만. 회원 상세는 자기 휴회 섹션이 있다) |

## 3. 설계 의사결정

| 결정 | 이유 | 버린 대안 |
| --- | --- | --- |
| 목록 부품 하나를 회원 상세와 내 회비가 같이 쓴다 | 회원과 재무님이 같은 화면을 보며 이야기할 수 있다 | 회원 상세를 본인에게도 열기 — 관리 화면 곳곳에 권한 분기가 생긴다 |
| | | 대시보드 표의 본인 줄만 — 금액·입금일이 없다 |
| 칸 상태는 `buildMemberYearStatus`의 `cells`를 그대로 쓴다 | 대시보드·엑셀·카톡 이미지와 같아야 한다. 테스트로 대시보드 응답과 비교한다 | 화면에서 따로 계산 |
| 데이터를 다 맞추기 전에도 바로 보인다 (2026-11-28 사용자 결정) | 대신 반영 시각을 적어 "언제 버전인지"를 알린다 | 재무님이 켜는 공개 스위치 |
| 확인 중 입금은 `MATCHED`·`ERROR`, 회비, 불확실한 매칭이 아닌 것 | 금액이 단가와 안 맞아 `ERROR`가 된 입금도 그 회원 것이다. 동명이인 등 `needsReview`는 다른 사람 입금일 수 있다 | `MATCHED`만 |
| 미납 요약은 고른 해만 센다 | 재무님 표가 해마다 따로다 | 모든 해 합계 |
| 한 달의 기준 금액은 직접 추가의 기본 금액과 같은 함수(`suggestedManualAmount`) | 부부면 부부 월 단가의 반 — 입금 확정이 부부 입금을 나누는 방식과 같다 | 새 계산 |
| 직접 추가의 "기타" 글은 임원에게만 보인다 | 임원끼리 보려고 쓴 글이 회원에게 그대로 나가지 않게 한다. 정해진 사유는 회원에게도 보인다 | 모두 보이기 |
| 휴회·면제·해당 없음 칸에 걸린 납부도 보인다 | 숨기면 회원 화면에서 낸 돈이 사라진 것처럼 보인다 | 칸 상태대로 숨기기 |
| 회원 한 명을 읽을 때는 휴가중·탈퇴 회원도 계산한다 | 임원은 탈퇴 회원 상세도 연다. 휴가중 회원도 메뉴가 보인다 | 대시보드처럼 승인·탈퇴만 |

## 4. 백엔드 처리

- **`GET /api/clubs/[id]/members/[userId]/fee-history?year=`**
  - `year`가 없으면 올해(한국 시각), 정수 1 이상이 아니면 400 "연도를 확인해주세요".
  - 요청자가 승인 상태 임원이거나, 본인이면서 회원 기능을 쓸 수 있는 상태(승인·휴가)여야 한다. 아니면 403 "권한이 없습니다". 대상이 없으면 404.
  - `loadMemberYearData(prisma, clubId, year, { clubMemberId })`로 그 회원만 읽고 `buildMemberYearStatus`로 칸을 정한다.
  - 납부는 그 회원의 모든 해를 한 번 읽어 고를 수 있는 연도(`selectableYears`)에도 쓴다. 묶인 입금은 id로 읽어 거래일·입금자명을 붙인다. 입금자명이 회원 이름과 같으면(앞뒤 공백 무시) 빼고 보낸다.
  - 확인 중 입금은 `paymentRecordMatchedMember`에서 이 회원의 입금 id를 얻어 상태·분류·검토 조건으로 거른다.
  - 반영 시각은 클럽 입금 내역의 가장 늦은 거래일시(상태 무관)다. 대시보드의 `latestTransactionDate`와 같다.
  - 회비 대상 아님 회원은 `months`·`pendingDeposits`를 비우고 `member.feeExcluded: true`로 보낸다.
- **`GET /api/clubs/[id]/custom/menu`**가 `feeMenuEnabled`(활성 회비 유형 수 > 0)를 함께 보낸다.

## 5. 프런트 처리와 UX 디테일

- `MemberFeeHistorySection`이 `useMemberFeeHistory`로 읽어 `MemberFeeHistoryView`에 넘긴다. 연도는 처음엔 서버가 정한 해이고, `OptionPicker`로 고르면 그 해를 다시 읽는다.
- 해당 없음·아직 오지 않은 달은 납부가 걸렸을 때만 줄을 보인다.
- 상태 칩 색은 `statusTone.ts`의 `feeMonth`: 낸 달 긍정, 미납 부정, 나머지 중립.
- 회원 상세에서 휴회 저장·삭제, 이월, 직접 추가·삭제, 시작월·탈퇴 정보 저장을 하면 납부 이력 캐시(`memberFeeHistory`)를 비운다.
- 미리보기: `/dev/screen-preview?screen=my-fee`, `/dev/admin-preview?screen=fee-member`. 회원 미리보기의 화면 고르기는 다섯 개가 되어 `OptionPicker`로 바꿨다.
