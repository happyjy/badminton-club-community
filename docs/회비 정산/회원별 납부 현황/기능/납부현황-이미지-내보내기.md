# 납부현황 이미지 내보내기 (카톡 공유용 PNG)

작성일: 2026-11-26
관련 화면: `/clubs/[id]/membership-fee` (회비 관리 대시보드 — [이미지로 내보내기])
설계 문서: [`2026-11-26-fee-status-image-export-design.md`](../../../superpowers/specs/2026-11-26-fee-status-image-export-design.md)
관련 파일:

- `src/lib/membership-fee/feeStatusSheet.ts` — 표의 줄(`buildFeeStatusSheet`), 40명씩 나누기, 칸 색. 엑셀과 이미지가 같이 쓴다
- `src/lib/membership-fee/feeStatusExport.ts` — 내보낼 회원과 반영일 읽기 (`loadFeeStatusExport`, 서버)
- `src/pages/api/clubs/[id]/membership-fee/export-sheet.ts` — `GET ?year=` 표의 줄을 JSON으로
- `src/lib/membership-fee/feeStatusImage.ts` — 캔버스에 그리기 (`renderFeeStatusImages`, `paintFeeStatusPage`)
- `src/lib/deliverFiles.ts` — 공유 창·내려받기 고르기
- `src/hooks/membership-fee/usePaymentDashboard.ts` — `useBuildFeeStatusImages`
- `src/components/organisms/membership-fee/FeeDashboardView.tsx`, `src/pages/clubs/[id]/membership-fee/index.tsx`

## 1. 배경 (Why)

- **재무는 납부현황표를 카톡방에 이미지로 올린다.**
  - 엑셀만 내보낼 수 있어, 엑셀을 열고 인쇄 쪽을 캡처하는 손작업이 들었다.
  - 재무의 기존 이미지는 A4 세로 한 쪽씩 캡처한 JPG 3장이다(793×1122, 38·42·12명).

## 2. 도입한 개선

- **대시보드의 [이미지로 내보내기]가 보고 있는 해의 표를 40명씩 나눈 PNG로 만든다.**
  - 지금 회원만 싣는다. 그 해에 탈퇴한 회원은 엑셀에만 있다.
  - 휴대폰: "이미지 N장을 만들었습니다." 확인 창의 [공유하기]를 누르면 공유 창이 열리고, 카톡을 고르면 여러 장이 한 번에 간다.
  - PC: PNG를 차례로 내려받고 "이미지 N장을 내려받았습니다."를 보인다.
  - 파일 이름: `회비납부현황_YYYY_YYYYMMDD_1.png`, `_2.png` … (날짜는 반영일, 엑셀과 같다)
- **한 장의 모양은 재무의 표·엑셀과 같다.**

| 항목 | 내용 |
| --- | --- |
| 크기 | 가로 800 기준 배치를 2배로 그려 가로 1600px. 40명이면 세로 2304px, 마지막 장은 남은 줄만큼 |
| 장마다 | 제목, 반영일, 범례, 머리글, 회원 최대 40명, 아래 쪽 번호 `- n -` |
| 싣는 회원 | 지금 회원(활동 회원)만. 2026-11-26 운영 데이터로 92명 → 3장(40·40·12) |
| 줄 순서·비고·굵은 선 | 엑셀과 같은 `buildFeeStatusSheet`. 탈퇴 회원을 빼고 계산해, 마지막 회원 아래에 굵은 선이 없다 |
| 칸 색 | 엑셀의 `CELL_FILL`. 라이트·다크와 상관없는 고정 색 |
| 병가 칸 | 색만 칠하고 사유는 적지 않는다(엑셀과 같다) |
| 긴 이름 | 칸에 들어갈 때까지 글자를 9px까지 줄인다 |

## 3. 설계 의사결정

| 결정 | 이유 | 버린 대안 |
| --- | --- | --- |
| PNG | 단색 칸과 글자라 JPG보다 또렷하고 파일이 작다 | JPG — 글자 둘레가 번진다 |
| | | PDF — 카톡에서 사진처럼 바로 안 보인다 |
| 40명씩 여러 장 | 한 장으로 길게 만들면 카톡이 줄일 때 이름이 흐려지기 쉽다. 회원들이 익숙한 재무의 표와 같다 | 한 장 |
| 브라우저가 캔버스에 직접 그린다 | 새 라이브러리 없이 화면 글꼴(Pretendard)로 그리고, 공유 창으로 바로 보낼 수 있다 | 화면을 사진 찍는 라이브러리 — 웹 글꼴 넣기가 느리고 브라우저마다 다르다 |
| | | 서버에서 PNG — 한글 TTF를 저장소에 넣어야 한다 |
| 줄 계산을 엑셀에서 떼어 같이 쓴다 | 엑셀과 이미지의 줄 순서·비고가 어긋날 수 없다 | 이미지용 계산을 따로 |
| 이미지에는 탈퇴 회원을 싣지 않는다 (사용자 결정) | 운영 데이터로 그리니 활동 92명 + 탈퇴 29명 = 4장(마지막 장 1명)이었다. 카톡방은 지금 회원만 보고, 재무의 표도 활동 회원만 싣는다 | 엑셀처럼 싣기 — 떠난 사람의 미납이 공개된다 |
| | | 싣되 장을 고르게(31·30·30·30) — 장이 하나 늘어난다 |
| 휴대폰은 확인 창을 한 번 거쳐 공유한다 | 브라우저는 누른 직후에만 공유 창을 열게 한다. 데이터를 받고 그리는 사이 그 시간이 지나 아이폰 사파리에서 막히기 쉽다 | 버튼을 누르면 바로 공유 — 막히면 내려받기로만 끝난다 |
| 공유는 터치 기기에서만 | PC는 파일이 필요한 경우가 많다 | 공유를 지원하면 PC도 공유 |
| 열 너비 NO 32 · 성명 76 · 월 48 · 비고 84 | "2026.02 탈퇴"가 비고 칸에 다 들어가야 한다 | 계획의 NO 40 · 비고 76 |

- **대가**: 공유가 막히면 내려받기로 넘어간다.
  - 아이폰에서 내려받은 PNG는 "파일" 앱에 저장되므로, 카톡으로 보내려면 한 번 더 골라야 한다.
- **대가**: PC 크롬은 여러 파일을 내려받을 때 처음 한 번 "여러 파일 다운로드" 허용을 묻는다.

## 4. 백엔드 처리

- **`GET …/membership-fee/export-sheet?year=YYYY`** (관리자) → `{ data: { sheet: { year, asOf, stamp, rows } } }`
  - 회원과 반영일은 엑셀 `export`와 같은 `loadFeeStatusExport`로 읽는다(회비 대상 아님 제외, 그 해 의무월·휴회월이 있는 회원).
  - 탈퇴 회원은 `buildFeeStatusSheet` 전에 뺀다.
  - `asOf`는 한국 날짜 `YYYY-MM-DD`, `stamp`는 `YYYYMMDD`다.
  - 연도가 없으면 한국 기준 올해, 이상하면 400 "연도가 올바르지 않습니다", 관리자가 아니면 403, 오류는 500 "납부현황을 불러오지 못했습니다".

## 5. 프런트 처리와 UX 디테일

- `useBuildFeeStatusImages`가 API를 불러 `renderFeeStatusImages`로 그린 뒤 PNG `File` 목록을 돌려준다.
  - 실패하면 서버가 준 사유, 없으면 "이미지를 만들지 못했습니다."를 토스트로 보인다.
- 그리기 전에 표에 들어갈 모든 글자로 `document.fonts.load`를 부른다. Pretendard는 글자 묶음별로 나뉘어 있어, 미리 받지 않으면 대체 글꼴로 그려질 수 있다. 글꼴을 못 받아도 그리기는 한다.
- `deliverFiles`는 `(pointer: coarse)`이고 `navigator.canShare({ files })`일 때만 확인 창을 거쳐 공유한다.
  - 확인 창이나 공유 창을 닫으면 아무 안내도 하지 않는다.
  - 공유가 `AbortError` 말고 다른 오류로 막히면 내려받는다.
  - 내려받을 때 파일 주소는 40초 뒤에 지운다. 사파리는 누른 직후 지우면 받기에 실패할 수 있다.
- 툴바의 [납부현황 내보내기] 옆에 버튼을 둔다. 휴대폰에서는 두 버튼이 오른쪽에 위아래로 놓인다.
- 미리보기: `/dev/admin-preview?screen=fee-status-image` — 지어낸 이름의 가짜 회원 44명으로 그린 2장. 저장소가 공개라 실제 회원 이름을 쓰지 않는다.
  - `&clubId=1&year=2026`을 붙이면 로그인한 관리자로 실제 데이터를 불러 그린다.
