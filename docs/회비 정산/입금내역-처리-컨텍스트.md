## 2. 구현 완료된 기능

- 엑셀 업로드 → 회원 매칭(7단계: 정확, 부부, 부분, 성 생략, 2글자, 부부 단일, 유사도)
- 가입비(FeeType "가입비") 미매칭 처리
- 회비 유형 관리(FeeType CRUD), 월·연납만(분기·반기 주석 처리)
- 회비 금액 관리(FeeRate) - 유형별·연도별·주기별 설정
- 확정 시 연도 선택(전년/당년/내년) + 다중 연도·월 선택 지원
- 월 선택: 단일 / Ctrl+토글 / Shift+범위 선택·해제
- 확정 취소(unconfirm), 건너뛰기(skip/unskip) 지원
- 일괄 확정(bulk-confirm) 지원
- 부족/초과 입금 처리 (부족 시 균등 배분, 초과 시 미할당)
- **회비 의무 시작 규칙**: 시작월 기준 (15일 규칙에서 변경), `feeObligationStartAt` 기반
- **휴회/병가**: MemberLeave 등록, 의무 월에서 제외, 대시보드 표시
- **회비 관리 대시보드** – 회원별 납부 현황 테이블 필터(입금 확정 결과 집계 기준)
  - UI: 세그먼트 버튼 **전체 / 미납 있음 / 납부 완료**(라디오 아님)
  - **미납 있음**: 선택 연도 의무 월 중 한 달이라도 미납이면 표시(일반·부부만, 면제 제외). 헬퍼 `memberHasAnyUnpaidMonthInYear`
  - **납부 완료**: **1월 ~ 사용자가 고른 달까지** 의무 월 중 모두 납부한 회원만 표시. 드롭다운 `N월까지`. 헬퍼 `memberFullyPaidThroughMonth(member, N)`. 연도 변경 시 기준 달은 당해 연도면 이번 달, 아니면 12월로 초기화
  - 휴회 월은 "의무 없음"으로 표시 — 미납/납부완료 판정에서 제외
  - 상세 기획·스펙: `@docs/회비 정산/입금내역-정렬-필터-기획.md` §8

## 3. 핵심 플로우

1. **엑셀 업로드** → PaymentUploadBatch + PaymentRecord 생성, `matchedMembers`(다중 회원) 저장, `lastPaidYearMonth` 첨부
2. **검토·수정** → 회원 매칭 수정, 매칭 실패 시 건너뛰기
3. **확정** → 선택 연도·월로 MembershipPayment 생성, 상태 CONFIRMED
4. **일괄 확정** → 매칭된 건만 선택 후 일괄 확정 (부족 건은 실패 처리)
5. **확정 취소** → MembershipPayment 삭제, 상태 MATCHED로 복귀
6. **건너뛰기** → 상태 SKIPPED, 필요 시 unskip으로 복귀

## 4. 주요 데이터 모델

- **PaymentUploadBatch**: clubId, uploadedById, fileName, recordCount — 엑셀 업로드 단위
- **PaymentRecord**: batchId, depositorName, amount, matchedMemberId, status, matchedMembers(다중)
- **PaymentRecordMatchedMember**: paymentRecordId, clubMemberId (다대다 매칭)
- **MembershipPayment**: clubMemberId, year, month, amount, period, paymentRecordId, confirmedById
- **FeeType**: 회비 유형 (일반, 부부 등)
- **FeeRate**: 유형별 연도·주기별 금액
- **MemberFeeType**: 회원별 유형 지정 (1인 1유형)
- **CoupleGroup/CoupleMember**: 부부 그룹 관리
- **FeeExemption**: 연도별 면제 (사유 포함)
- **MemberLeave**: 휴회 기간 (startYear/startMonth ~ endYear/endMonth, null=장기)
- **ClubMember.feeObligationStartAt**: 회비 의무 시작 시점

## 5. 추가 작업 시 참고

- `handleConfirm(recordId, year, months)` 시그니처
- confirm API: matchedMembers 우선, 없으면 matchedMemberId 사용
- 부부 2명 매칭(동일 부부 그룹 전원): 월 합계는 coupleAmount 1회(세대당); 일괄 확정 시 MembershipPayment는 합계 coupleAmount가 되도록 인원 수로 균등 분배
- 다중 연도·월 선택: `selections` 배열로 (예: 2025년 12월 + 2026년 1월 동시 확정)
- 금액 검증: FeeRate 목록 기반 (`validateAmountWithRates`)
- 월 제안: 의무 월(obligationMonths) 기반, 미납 월 우선 (`suggestMonths`)

## 6. 입금 부족/초과(부분 납부) 처리

- **부족**: 커플 2명 50,000원 예상인데 40,000원만 입금 후 나중에 10,000원 추가 납부
- **초과**: 월회비 25,000원 + 가입비 100,000원 = 125,000원 한 건 입금 시, 1개월 월회비만 인정
- **업로드**: 금액이 1개월 예상액 미만이어도 회원 매칭되면 MATCHED 저장
- **확정**: 입금액 < 예상액 → 부족 확정(금액 균등 배분) / 입금액 >= 예상액 → 선택한 월·인원만큼만 확정(초과분 미할당)
- **일괄 확정**: 부족 건은 실패 처리, "개별 확정에서 월 선택 후 부족 확정해주세요" 안내

### 구현 요약

| 구분          | 파일              | 변경 내용                                                                                        |
| ------------- | ----------------- | ------------------------------------------------------------------------------------------------ |
| 업로드 API    | `upload.ts`       | 회원 매칭됐는데 금액 검증 실패 시, 1개월 예상액 미만이면 `MATCHED` 저장                          |
| 확정 API      | `confirm.ts`      | 입금액 >= 예상액 → 선택한 월만 확정(초과분 미할당) / 입금액 < 예상액 → 부족 확정(금액 균등 배분) |
| 일괄 확정 API | `bulk-confirm.ts` | 부족 건 실패, 사유: "입금 부족 - 개별 확정에서 월 선택 후 부족 확정해주세요"                     |

### 사용 흐름 예시

**커플 2명, 50,000원 예상, 40,000원 입금:**
1. 엑셀 업로드 → 회원 매칭 시 `MATCHED`로 저장
2. 입금 내역 처리 페이지에서 해당 건 선택
3. 연도·월 선택 후 확정 → 2명 각 20,000원으로 확정
4. 나중 10,000원 추가 입금 시 별도 PaymentRecord로 업로드 후 확정

**1명, 월회비 25,000 + 가입비 100,000 = 125,000원 한 건:**
1. 엑셀 업로드 → 회원 매칭 시 `MATCHED`로 저장 (125,000 = 25,000×5이므로 5개월 제안될 수 있음)
2. 1개월만 선택 후 확정 → 25,000원 1개월 회비로 확정, 초과분(가입비 100,000원)은 미할당
3. 가입비는 별도 정산 또는 현장에서 처리
